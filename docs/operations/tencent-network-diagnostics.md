Tencent range network diagnostics are opt-in through `includeNetworkDiagnostics`. Ordinary detail reads keep the existing path. `status: succeeded` means the scoped read completed; guest NIC setup and end-to-end connectivity remain unverified.

The service checks the range owner, exact unreleased CVM ledger identities and frozen provider/context/UID/region/zone. The helper reads only persisted CVM, subnet, SG, ACL, route-table, NAT and EIP IDs. The CVM-created primary ENI is discovered by the proven CVM attachment and VPC; any auxiliary ENI must already be persisted. Exact-ID re-reads reject changed attachments, foreign account IDs, extra NICs and ambiguous device indexes. Actual MAC/IP/DeviceIndex are reported, independent of the planned logical NIC index.

All list responses require stable TotalCount, unique identities, complete arrays and bounded pagination. Resource tags are checked with persisted source identity, never used to adopt resources. Read-only API RequestIds and frozen context identity are returned; credentials, custom tags and raw responses are excluded. External SG templates, five-tuple ACLs and non-subnet SNAT rules fail closed because the current OpenTofu range module does not create them. Rule references never trigger queries of external resources. Missing ACL Priority remains unknown rather than being inferred from response position. Routes report whether the next hop matches a known range target.

- [DescribeRouteTables](https://cloud.tencent.com/document/product/215/15763), [DescribeRoutes](https://cloud.tencent.com/document/product/215/111309). Table pagination uses strings; route pagination uses integers and frozen route-table/VPC filters.
- [DescribeSecurityGroupPolicies](https://cloud.tencent.com/document/api/215/15804), [DescribeNetworkAcls](https://cloud.tencent.com/document/product/215/42160), [VPC data structures](https://cloud.tencent.com/document/product/215/15824).
- [DescribeNatGateways](https://cloud.tencent.com/document/product/215/36034), [DNAT rules](https://cloud.tencent.com/document/product/215/36717), [SNAT rules](https://cloud.tencent.com/document/product/215/52620), [DescribeAddresses](https://cloud.tencent.com/document/api/215/16702).
- The pinned upstream provider defines [DNAT](https://github.com/tencentcloudstack/terraform-provider-tencentcloud/blob/e0d222151a29d44795492d68a1076d55ec006cdb/tencentcloud/services/vpc/resource_tc_dnat.go) IDs as `PROTOCOL://VpcId:NatId@PublicIp:PublicPort` and [SNAT](https://github.com/tencentcloudstack/terraform-provider-tencentcloud/blob/e0d222151a29d44795492d68a1076d55ec006cdb/tencentcloud/services/vpc/resource_tc_nat_gateway_snat.go) IDs as `NatId#ResourceId`. These are matched to the persisted manifest and authoritative API tuples, not parsed as Aliyun NAT table IDs.

Validation uses synthetic responses in Docker with networking disabled. No live Tencent queries, writes, VNC requests, auxiliary-IP tests or image imports were performed by this adapter's author.
