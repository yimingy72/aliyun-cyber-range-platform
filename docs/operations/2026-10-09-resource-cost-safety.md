# 云资源回收与费用安全审查（2026-10-09）

审查范围：单实例（OpenTofu 与遗留原生 API）、编排创建/更新/销毁、共享网络、镜像制作/导入、快照与账单同步。本文不把平台终态当成云端清理证明，也不把缺少账单当成没有费用。

## 已修复的风险

| 风险 | 修复后的行为 |
| --- | --- |
| 创建请求已经发出，但响应、state 或整个工作目录丢失，重试可能再次创建 | 在数据库写入创建意图，并保存固定任务身份、账号和地域；未知结果只能恢复原任务，不能盲目重新 apply/RunInstances/ImportImage。 |
| 空列表、残缺分页、HTTP 200 业务错误被当成资源不存在 | 校验响应身份、RequestId、分页完整性和预期资源 ID；无法证明时保留失败状态、库存和账本。 |
| OpenTofu 返回成功后立即显示回收，或先结束实例再释放账本 | 独立核验已知 ECS、磁盘、网络等资源消失，释放账本成功后才写入销毁终态；失败保留可恢复材料。 |
| 失败创建留下的资源未进入费用台账 | 先从 state/云端精确归属恢复物理 ID，保存库存并登记账本，再尝试补偿清理。 |
| worker 租约丢失后仍继续调用云 API 或提交旧结果 | 请求前检查持有权；编排进程接收中止信号；写回使用租约/作业开始时间作为条件，旧 worker 不能覆盖新结果。 |
| 云账号切换导致用当前账号查旧实例，误判不存在 | 冻结原账号上下文、UID、地域；无法确认来源的历史实例拒绝云操作和“已回收”结论。 |
| 完整镜像创建 ECS 时自动携带的数据盘未被计入 | 盘点并保存真实系统盘、数据盘、归属证明；无来源证明的外部盘不自动认领或删除。独立磁盘未消失时保留回收失败和有效账本。 |
| 编排更新移除旧节点后，旧磁盘 ID 随新拓扑被覆盖 | 单独保留退役资源清单，已知收费资源逐项核验消失后才关闭对应账本；残留继续显示待回收。 |
| 镜像导入未知响应、失败清理遗漏 backing snapshots | 持久化提交意图和唯一来源；按原账号恢复，不重复导入；镜像及每个自有快照逐项检查依赖、删除并验证消失，记录断点。 |
| 云标签写入失败导致没有资源账本 | 已确认来源的精确资源 ID 先入账本，之后才补标签；标签失败不抹去计费身份。 |
| 账单分页缺失、跨账号冲突或同步失败覆盖历史 | 完整读取并校验账号、日期、分页、金额；按账号/账日原子替换，错误保留原数据，归属冲突进入异常费用。 |
| 只增量同步最新日期，漏掉迟到或修订账单 | 默认手动同步重刷最近七个完整账日；API 每六小时重刷上月及本月完整账日，worker 不重复启动定时器。更早调整可指定日期补刷。 |
| 汇总费用或尚未出账资源被误读为零费用 | 显示“未归属费用”“尚未匹配账单资源数”和暂定金额；不同币种分别汇总，不能把地区级快照或 OSS 汇总随意分给用户。 |

## 镜像和快照费用

当前平台“打包镜像”实现的是 CreateImage，另有 ImportImage；没有 ExportImage 到 OSS 的路径。从 ECS 制作镜像时，每块磁盘会生成快照；只要保留可用的云镜像，其依赖快照通常也必须保留，并产生存储费用。删除源 ECS 不会自动删除这份镜像和快照。

不再保留云镜像时，先删除镜像，再删除已证明属于该制作任务、且没有其它镜像/磁盘引用的快照。不能先删仍被镜像依赖的快照，也不能强制删除外部或来源不明的快照。仅移出平台目录不等于删除云资源。

阿里云 ExportImage 导出到 OSS 后，OSS 文件仍有存储、请求及可能的下载流量费用。确认导出文件可用且不再需要原云镜像后，才清理原镜像和所属快照；OSS 文件的保留策略需要另行管理。

## 恢复原则

1. 创建结果未知：保留数据库创建意图、原账号和 OpenTofu state/marker，先按精确标签和已知 ID 查询原请求结果；不得删除工作目录后直接重试创建。
2. 销毁失败：先检查是否云 API 暂时不可用、账号权限变化或有仍存活的磁盘/网络；以原账号和已有 state 重试回收，不新增替代资源。
3. 未证明归属的磁盘：不采用“挂在平台 ECS 上”“创建时间相近”作为删除授权；保留异常和材料。自有但 `DeleteWithInstance=false` 的磁盘不会伪装成已回收，需要单独处理后重新核验。
4. 账单：区分资源台账与 BSS 已出账金额。每个可能计费资源先有台账，BSS 出账后匹配；未出账和无法细分的费用保持可见。
5. 历史未知账号/丢失 state：先恢复来源证明；现有数据不足时明确保留待核验，不能用新账号的空查询替代旧账号的清理证明。
