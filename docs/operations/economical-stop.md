# ECS 节省停机与预约

适用于阿里云按量付费 VPC ECS，包括单实例、单实例批次、编排实例与有平台启动回执的编排批次。腾讯云、dry-run、本地盘和持久内存规格不执行此模式。支持立即节省停机、恢复原 ECS、一次性预约、修改预约、取消预约和只读核验原任务。

## 使用与计费边界

列表的“更多”菜单和编排详情的“启停管理”入口先核对准确实例/节点和原到期时间，再单独确认影响。菜单按平台记录禁用不适用的启停项，查看启停任务保留核验与恢复入口；最终仍以实时云端预览和核验为准。预约时间统一显示为北京时间。只有官方返回 `Stopped` 和 `StopCharging` 才显示“节省停机”；普通停机不计作成功。恢复必须核验原实例 `Running`，有系统公网入口时同时等待公网 IP 并刷新入口。

保留原 ECS ID、磁盘、私网 IP、网卡及原到期销毁时间。释放计算资源可能丢失系统公网 IP，恢复还受库存和余额限制。云盘、快照、EIP、NAT 等保留资源仍可能计费，账单台账不会因停机标记释放、归零或停止同步。不会重建实例、换规格或隐式延长到期时间。

[阿里云节省停机文档](https://help.aliyun.com/en/ecs/user-guide/economical-mode)

## 预约和任务可靠性

- 未来预约持久存储于 `RangeInstance.powerControl.schedule`，不提前占用活动作业槽，也不阻止正常使用；每个实例仅一份未来预约，修改和取消校验准确预约 ID 与版本。
- worker 到点重新检查原 workspace/账号、owner、操作者当前权限、来源和原到期时间后，转换为 `economical_stop` 作业。遇到其他活动任务或镜像打包最多等待 5 分钟，错过窗口会失败，不无限延迟补发。
- 立即操作和预约执行均复用持久 ProvisionJob 与租约，逐主机记录唯一请求意图、云回执和原实例实况。服务重启后继续观察同一作业，不自动补发已记录意图的 Stop/Start。
- 失败任务可“核验原任务”。该入口只观察原 ECS，不发送新的电源指令；仍需新动作时须等待原任务完成核验并重新预览/确认。
- 创建、更新、打包、节点动作与执行中的电源任务互斥；处于节省停机/未知状态的实例须先恢复或核验，仍可按原生命周期销毁。批次基于持久父子关系或独立启动回执，不能靠名称猜测。

## API

`/admin/instance-power/:kind/:id` 的 `kind` 为 `single`、`single_batch`、`range` 或 `range_batch`；编排批次 ID 需 URL 编码。

- `GET /`：成员、预约、任务与安全步骤摘要。
- `GET /preview?action=economical_stop|resume&scheduledAt=<带时区 ISO>`：只读预览；仅节省停机支持预约。
- `POST /`：提交 `action`、`planDigest`、可选 `scheduledAt`，必须保留相同幂等键并完成服务端二次确认。
- `POST /cancel`：提交准确 `schedules:[{instanceId,scheduleId,revision}]`。
- `POST /jobs/:jobId/verify`：核验原任务，不重发电源操作。

读操作使用对应 `instances:read` / `ranges:read`，预览和变更使用对应 `*:control`，同时受 workspace、只读历史空间和 owner/admin 校验约束。

## 发布与回滚

增量迁移 `20261022010000_economical_stop` 增加两个作业枚举和一个可空 JSON 字段，不改写现有实例。先备份数据库、源文件及现有 API/web/worker 镜像，构建三个服务，运行迁移后成组更新。保留原 DNS 覆盖文件和 provider/workspace 挂载，不操作现有云资源。

旧版本 worker 不识别新增作业类型。回滚前必须停止新任务入口，确认没有 pending/running 电源作业及未来预约；不能只降级 worker 后让它消费新作业。保留增量字段/枚举，不使用删列删枚举或数据库全量恢复来回滚，以免覆盖发布后的正常用户数据。

容器回归覆盖模式识别、原资源身份、计费保留、二次确认、预约 CAS/重启/权限变更、未知回执不重发、原任务核验与到期销毁并发。真云 smoke test 必须另有明确授权，只对本次新建临时资源执行，结束立即通过平台回收。
