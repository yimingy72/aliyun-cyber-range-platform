`single_instance_cloud_resource_status` retains its original `exists`, `instanceIds` and tag-matched instance fields. `exists: false` means the CVM/ECS tag query is empty; it says nothing about retained disks.

Tencent responses additionally contain `recordedResourceStatus`. It queries only exact CVM/CBS/EIP/NAT IDs already stored in this instance's frozen inventory or billing ledger, including released historical rows. The selected workspace, owner, batch, provider, UID, original context ID, region and zone must match before the cloud query. A historical ID missing from current inventory requires the same source job's context-bound creation-inventory log. Retired inventory must retain the same original context. The tool accepts only a platform single-instance ID, never caller-provided cloud resource IDs.

Each result identifies the physical ID, inventory/ledger sources and ledger IDs. Successful empty responses retain the cloud API action and all RequestIds. A returned disk counts as present regardless of attachment, charge type or recycling state. Permissions, business errors, malformed responses, changed totals, duplicate/unrequested IDs and truncated pagination remain failures, never absence.

`allKnownAbsent` applies only to the persisted compute resource IDs checked in the result. It is `null` for an empty set, excluded disks without ownership proof or ledger types whose retention lifecycle was not queried. The field does not assert that the account has no other resources, that all bills arrived or that future charges are zero. This read does not update billing rows, lifecycle state or cloud resources. Alibaba Cloud responses remain unchanged.

The [official DescribeDisks contract](https://cloud.tencent.com/document/api/362/16315) requires Region, permits DiskIds or Filters separately and returns DiskSet/TotalCount/RequestId. The adapter supplies nonempty known DiskIds, reads all pages and verifies response identities. An attachment-filter empty response cannot prove a detached disk is gone. Empty input causes no account-wide disk query.

Docker verification uses synthetic responses with networking disabled; no direct live SDK, cloud or database calls were performed.

[DescribeSecurityGroups](https://cloud.tencent.com/document/api/215/15808) explicitly defines `ResourceNotFound` as a missing resource. Only a known-ID lookup of that API with the exact error code and a valid original RequestId is accepted as absence. A multi-ID error is split into individual read-only lookups so a retained group cannot disappear from the result. Tag/filter queries, missing RequestIds, other error codes and other API kinds remain failures. Error RequestIds are validated and retained without vendor messages or credentials.
