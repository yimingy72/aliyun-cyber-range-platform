# ECS 节点独立镜像解析设计

## 目标

综合靶场模板中的每个 ECS 节点必须显式选择镜像，并在 OpenTofu 下发时使用该节点自己的精确阿里云镜像 ID。一个节点的镜像不能成为其他节点的隐式回退值。

## 范围

- 新建 ECS 节点的镜像相关默认值为空。
- 模板保存和实例创建前校验每个 ECS 节点都已选择镜像。
- 每个 host 独立解析和下发 `image_id`。
- 兼容已保存的无版本公共镜像别名，例如 `ubuntu_22_04_x64_20G_alibase`。
- 将最终每节点镜像 ID 写入资源摘要，供详情页和诊断使用。

不包含对既有云资源的就地重装或替换；已创建的实例保持原状。

## 行为

### 模板编辑与校验

新建 ECS 的 `image`、`imageName` 和 `imageId` 均为空。用户未选择平台镜像资产时，前端不能保存模板或创建实例，并显示“请选择镜像”。后端使用同一规则校验拓扑快照，确保 API、MCP 或历史客户端不能绕过限制。

已存在的模板仍可加载。带精确镜像 ID 的节点直接使用该 ID；带旧式无版本公共镜像别名的节点在创建时解析为当前区域可售的带版本公共镜像 ID。空镜像的旧节点不会自动补默认 Ubuntu，而是被拒绝并提示选择镜像。

### 运行器与 OpenTofu

运行器为每个 host 建立独立镜像解析结果：

- 自定义镜像 `m-...` 及可用目录中的精确公共镜像 ID 直接校验并保留。
- 旧式无版本公共镜像别名仅匹配相同基础名称的可售带版本公共镜像；找不到时以节点键和原值报告失败。
- 不再将所有 host 镜像折叠为一个 `image_id`，也不再因多个不同镜像而报冲突。

渲染器在 `hosts[].image_id` 中写入每节点精确镜像 ID。根 wrapper 和 enterprise-range 模块将该字段声明为必填；`alicloud_instance.hosts` 使用 `each.value.image_id`。遗留的全局 `image_id` 参数从综合靶场渲染路径移除，不再参与 ECS 镜像选择。

资源摘要新增 `resolvedImageIds: Record<string, string>`。保留现有 `resolvedImageId` 仅作向后兼容，它取入口 ECS 的最终镜像 ID。

## 失败处理

- 空镜像：保存和创建均拒绝，明确指出对应 ECS 节点。
- 旧别名没有可售匹配项：创建在渲染前失败，不调用 OpenTofu apply。
- 精确镜像在当前区域不可用：创建在渲染前失败，不调用 OpenTofu apply。

## 验证

测试按 TDD 增加以下覆盖：

1. 新建 ECS 默认镜像为空，未选镜像不能保存或创建。
2. 两个 host 使用不同精确镜像（公共 `.vhd` 与自定义 `m-...`）时，生成的 tfvars 和模块计划各自保留对应 ID。
3. 旧式 Ubuntu 22.04 别名解析到当前可售的版本化公共镜像，不会采用另一 host 的镜像。
4. 空镜像、不可用精确 ID 和无法匹配的旧别名均在 apply 前失败。
5. Docker 容器中执行相关 API、Web、OpenTofu 测试，并构建更新后的 API、worker、Web 镜像。
