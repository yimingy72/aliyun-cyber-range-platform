# ECS 节点独立镜像解析设计

## 目标

综合靶场模板中的每个 ECS 节点必须显式选择镜像，并在 OpenTofu 下发时使用该节点自己的精确阿里云镜像 ID。一个节点的镜像不能成为其他节点的隐式回退值。

## 范围

- 新建 ECS 节点的镜像相关默认值为空。
- 模板保存和实例创建前校验每个 ECS 节点都已选择镜像。
- 每个 host 独立解析和下发 `image_id`。
- ECS 镜像仅允许引用当前用户可访问的平台镜像中心资产以及当前用户自己的镜像。
- 将最终每节点镜像 ID 写入资源摘要，供详情页和诊断使用。

不包含对既有云资源的就地重装或替换；已创建的实例保持原状。

## 行为

### 模板编辑与校验

新建 ECS 的 `image`、`imageName` 和 `imageId` 均为空。用户只能从平台镜像中心中自己有权使用的镜像资产，或当前用户自己的镜像中选择镜像；列表不展示阿里云公共镜像，也不接受手填的阿里云镜像 ID。用户未选择任一允许来源的镜像时，前端不能保存模板或创建实例，并显示“请选择镜像”。后端使用同一规则校验拓扑快照，确保 API、MCP 或历史客户端不能绕过限制。

平台镜像中心资产与用户自有镜像是仅有的可信来源：拓扑保存来源标识与展示信息，运行时从对应记录取得实际阿里云 `imageId`，并按当前用户的可见性、归属和启用状态校验。管理员必须先将公共镜像收录至平台镜像中心，用户才可以使用它。

已存在的模板仍可加载，但任何空镜像、未关联允许来源或直接引用阿里云公共镜像 ID 的旧节点均不能保存或创建实例，必须重新选择已收录的平台镜像或自己的镜像。系统不再把 `ubuntu_22_04_x64_20G_alibase` 等别名解析成公共镜像，也不为旧模板自动补默认镜像。

### 运行器与 OpenTofu

运行器为每个 host 建立独立镜像解析结果：

- 每个 host 的平台镜像中心资产或用户自有镜像独立解析为来源记录的精确阿里云 `imageId`。
- 来源不存在、未启用、当前用户无权使用，或其镜像在目标区域不可用时，以节点键和来源标识报告失败。
- 不再将所有 host 镜像折叠为一个 `image_id`，也不再因多个不同镜像而报冲突。

渲染器在 `hosts[].image_id` 中写入每节点精确镜像 ID。根 wrapper 和 enterprise-range 模块将该字段声明为必填；`alicloud_instance.hosts` 使用 `each.value.image_id`。遗留的全局 `image_id` 参数从综合靶场渲染路径移除，不再参与 ECS 镜像选择。

资源摘要新增 `resolvedImageIds: Record<string, string>`。保留现有 `resolvedImageId` 仅作向后兼容，它取入口 ECS 的最终镜像 ID。

## 失败处理

- 空镜像：保存和创建均拒绝，明确指出对应 ECS 节点。
- 未关联、未启用或无权访问的平台镜像中心资产或用户自有镜像：保存或创建拒绝。
- 资产对应的精确镜像在当前区域不可用：创建在渲染前失败，不调用 OpenTofu apply。

## 验证

测试按 TDD 增加以下覆盖：

1. 新建 ECS 默认镜像为空，未选镜像不能保存或创建。
2. 两个 host 引用不同允许来源（一个平台资产记录公共 `.vhd`、另一个为当前用户自己的 `m-...` 镜像）时，生成的 tfvars 和模块计划各自保留对应 ID。
3. 模板不能保存或创建直接引用阿里云公共镜像 ID、未关联允许来源、无权访问平台资产或他人私有镜像、或引用未启用镜像的 ECS 节点。
4. 空镜像和资产对应的不可用精确 ID 均在 apply 前失败。
5. Docker 容器中执行相关 API、Web、OpenTofu 测试，并构建更新后的 API、worker、Web 镜像。
