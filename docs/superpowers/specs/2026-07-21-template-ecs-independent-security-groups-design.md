# 模板拓扑 ECS 独立安全组设计

**日期：** 2026-07-21  
**范围：** 仅综合靶场模板拓扑（`alicloud-enterprise-range`）。单实例创建流程及其共享 VPC／共享安全组策略不变。

## 背景

模板拓扑编辑器将 ECS 网卡的 `securityGroupRules` 初始化为空，因此不会展示有效的默认安全组规则。部署模块则在规则列表为空时，向一个共享安全组注入 TCP 22 和 TCP 80 的公网入方向规则。结果是：编辑器、保存的拓扑与云端有效规则不一致；并且同一靶场内的所有 ECS 共用安全组，无法对某一 ECS 独立编辑或删除规则。

## 目标

1. 每个模板拓扑 ECS 拥有独立的阿里云安全组，并只绑定到该 ECS。
2. 新建 ECS 在属性面板展示两条平台默认规则：TCP 22、TCP 80，来源 `0.0.0.0/0`，入方向、允许、优先级 1。
3. 用户可新增、修改或删除默认规则；保存的结果只影响所选 ECS。
4. 用户删除该 ECS 的全部规则后，部署空安全组，不能自动恢复平台默认规则。
5. 创建、更新／应用拓扑、删除 ECS 与销毁整套靶场均正确创建、变更或清理相应安全组和规则。
6. 交换机 ACL 语义不变：没有显式 ACL 时不创建、不绑定自定义 ACL。
7. 单实例流程继续共享既有 VPC 和安全组，保留其现有全端口开放策略；不得因本项改动改变其变量、资源或行为。

## 方案

### 拓扑数据语义

在模板拓扑 ECS 的主网卡规则数据中持久化 `securityGroupRulesMode`：

- `default`：未覆写平台默认，面板显示两条默认规则。
- `custom`：规则数组是权威配置；数组可以为空，表示该 ECS 的独立安全组没有任何用户规则。

新建 ECS 使用 `default` 模式。旧拓扑的兼容规则如下：缺少模式且规则数组为空时解释为 `default`；缺少模式但已存有规则时解释为 `custom`。这保持现有空数组模板的有效访问行为，并保留已有显式规则。

任何针对规则的新增、编辑或删除操作都会将该 ECS 切换为 `custom`，并保存当时的完整规则数组。默认规则只是初始值，不是不可编辑的只读提示。

### 编译与 IaC

编译器针对每个 ECS 生成有效安全组规则：

- `default` 模式物化为 SSH 和 HTTP 两条默认规则；
- `custom` 模式只生成用户保存的规则，包括空数组；
- 规则包含目标 ECS 键，供 IaC 精确绑定。

综合靶场 OpenTofu 模块把现有单个 `alicloud_security_group.range` 替换为以 ECS 键为 `for_each` 的安全组资源。每台 `alicloud_instance.hosts` 绑定自己的安全组 ID。安全组规则的资源地址以目标 ECS 键和规则键稳定标识，并绑定目标 ECS 的安全组。

模块不再在规则列表为空时添加全局兜底规则。默认规则必须由编译器明确传入；这样自定义空列表不会被错误地恢复为 SSH/HTTP。

当前多网卡资源和绑定方式不在本次扩展范围内；每台 ECS 的独立安全组先按当前 ECS 主网络接口的安全组绑定路径生效。

### 生命周期

- **创建：** 为每个 ECS 创建独立安全组及其有效规则，再将对应安全组绑定到 ECS。
- **更新／应用：** 依据新编译结果更新规则；新增 ECS 新建安全组，移除 ECS 删除其安全组和规则，其他 ECS 的安全组地址保持稳定。
- **整套靶场销毁：** 保持现有 OpenTofu destroy 路径。资源依赖确保先解绑／删除 ECS，再销毁各自安全组与规则。
- **失败重试与销毁重试：** 继续复用既有保存的工作区和 Terraform state，确保同一资源地址可被幂等识别和回收。

## 界面

ECS 属性面板的安全组区显示当前 ECS 的有效规则。默认模式下，初始两条规则使用“平台默认”标识。用户在任何一条规则上编辑、删除，或点击新增规则后，规则组转为自定义；该状态无需额外操作按钮。

交换机 ACL 面板继续只展示显式自定义 ACL；空数组应保持“暂无 ACL 规则”，不展示并不存在的云侧默认 ACL。

## 测试与验证

先测试后实现，覆盖：

1. 新增 ECS 在默认模式下显示 SSH/HTTP 两条规则。
2. 修改或删除默认规则会持久化为 `custom`，删除全部规则仍保留空配置。
3. 旧的空规则拓扑按默认模式读取，已有规则的旧拓扑按自定义模式读取。
4. 编译器为默认 ECS 物化两条规则，为自定义空配置物化零条规则。
5. 渲染器／OpenTofu 输入以 ECS 为单位创建安全组和绑定；不再生成共享安全组或模块级空列表兜底规则。
6. 更新、ECS 删除和整套销毁的 Terraform plan／state 地址能分别变更与回收对应安全组。
7. 单实例网络模块及其全端口共享安全组回归测试保持通过。

所有前端、后端和 OpenTofu 验证均通过 Docker 容器执行；代码改动后重建相关镜像并以容器态完成回归。

## 非目标

- 不修改单实例的网络拓扑、安全组或端口开放策略。
- 不创建、展示或模拟未显式配置的网络 ACL。
- 不将每个辅助网卡扩展为独立安全组绑定模型。
