# 单实例管理与后台导航调整设计

日期：2026-07-08
状态：Draft

## 当前实现快照

截至当前仓库状态，下面这些基础能力已经存在，可直接复用：

1. 平台已经有统一后台壳层、左侧导航、列表型工作台页面风格
2. 平台已经有 `RangeInstance + ProvisionJob` 的实例与任务主链路
3. 模板页 `生成实例` 已经有 `实例名 + 到期时间` 弹窗和启动 API
4. 节点级运行操作后端已经支持：
   - `重启`
   - `打开 VNC`
   - `二次打包镜像`
5. 平台已经有单 ECS OpenTofu 模块：
   - `infra/opentofu/modules/alicloud-vpc-single-ecs`
6. 平台已经有实例规格可售校验接口：
   - `GET /admin/system-config/instance-type-availability`
7. 平台已经有“平台收录镜像”目录，可供实例启动时选择镜像

当前还没有的能力主要是：

1. 后台没有独立的 `实例管理` 页面
2. 单实例还没有“复用默认网络”的创建方式
3. 模板列表没有 `创建人` 字段
4. 编排实例列表没有 `创建人` 字段

## 1. 背景

当前后台已经有：

1. `镜像中心`
2. `靶场编排`
3. `靶场实例`
4. `基础配置`

其中：

- `靶场编排` 的职责是维护 VPC、交换机、ECS 等资源组成的靶场拓扑模板
- `靶场实例` 的职责是基于靶场模板生成整套编排实例，并对实例生命周期进行管理

但平台还缺少一类更轻量的运维入口：

- 只创建单个 ECS 靶机
- 不要求每次都新建 VPC
- 不要求进入完整编排流程
- 更适合部门内日常临时靶机、镜像制作和基础验证

因此本次需要补一套 `实例管理` 能力，专门面向**单实例 ECS**。

## 2. 本次目标

本次设计覆盖五个目标：

1. 将当前 `靶场实例` 页面统一改名为 `编排实例`
2. 调整后台左侧导航顺序
3. 为模板列表和编排实例列表增加 `创建人` 字段
4. 新增 `实例管理` 页面，用于创建和管理单 ECS 实例
5. 为单实例补齐默认网络复用、生命周期管理、VNC、镜像打包与历史记录

## 3. 非目标

本次不处理以下内容：

1. 不做单实例详情页
2. 不做真实用户体系，`createdBy` 先固定为 `admin`
3. 不做公网 IP 开关，单实例默认分配公网 IP
4. 不做手动选择 VPC / 交换机 / 安全组
5. 不做复杂网络可视化和单实例拓扑展示
6. 不做批量编辑或批量运维面板
7. 不做多账号云资源治理能力

## 4. 核心设计结论

### 4.1 单实例管理复用现有实例体系

单实例管理不新建独立实例主表，也不新建独立任务体系。

继续复用：

1. `RangeInstance`
2. `ProvisionJob`
3. 现有 worker 分发与状态回写机制

但需要为 `RangeInstance` 新增实例模式区分：

- `range`：编排实例
- `single`：单实例

这样可以保证：

1. 编排实例和单实例的生命周期、历史、错误恢复、镜像打包链路共用一条主链
2. 前端页面层面只做“按模式分屏显示”
3. 后续接入用户体系时，也只需要改一条实例主链

### 4.2 单实例页面不做详情页

单实例不需要独立详情页。

页面形态固定为：

1. 列表表格
2. `实例列表 / 实例历史` 双视图
3. 右上角 `创建实例`
4. 行内 `更多操作`

单实例的运行操作直接放到列表行中完成：

1. 关闭实例
2. 重启实例
3. 打开 VNC
4. 打包为镜像

### 4.3 单实例默认复用一套持久化网络

平台需要维护一套**默认单实例网络**，其结构固定为：

1. 1 个 VPC
2. 3 个交换机
3. 1 个默认安全组

后续所有单实例都加入这套网络，不再重复创建 VPC。

安全组默认策略固定为：

- 放通全部端口

前端不再提供 `源 IP` 配置项。

### 4.4 交换机由系统自动分配

单实例创建时，交换机不由用户手动选择。

第一阶段采用最简单且可解释的规则：

1. 读取当前未销毁的单实例数量
2. 对默认网络中的 3 个交换机按固定顺序轮转分配

这样做的原因：

1. 内网 IP 并不是当前用户关心重点
2. 可以避免页面多一个无收益字段
3. 轮转策略足够满足第一阶段使用

### 4.5 镜像只允许来自“平台收录镜像”

单实例启动弹窗中的镜像字段不允许自由文本输入，也不允许直接操作阿里云公共镜像 / 自定义镜像原始列表。

镜像来源固定为：

- `平台收录镜像`

这样可以和当前平台镜像中心保持一致，并与“打包为镜像后自动收录”形成闭环。

### 4.6 创建人与实例命名先走轻量策略

当前后台还没有完整用户体系。

因此第一阶段的创建人策略固定为：

- 新创建模板：`createdBy = 'admin'`
- 新创建编排实例：`createdBy = 'admin'`
- 新创建单实例：`createdBy = 'admin'`

当单实例创建数量大于 1 时：

1. 用户输入的是实例名前缀
2. 系统自动扩展为：
   - `name-01`
   - `name-02`
   - `name-03`

## 5. 导航与命名调整

### 5.1 `靶场实例` 改名为 `编排实例`

当前页面与导航中的 `靶场实例` 统一改名为：

- `编排实例`

该改名仅改变产品命名，不改变已有编排实例路由与核心模型语义。

### 5.2 新的导航顺序

左侧导航顺序调整为：

1. `镜像中心`
2. `实例管理`
3. `靶场编排`
4. `编排实例`
5. `基础配置`

其中新增路由建议为：

- `实例管理`：`/admin/instances`

现有路由保留：

- `靶场编排`：`/admin/scenarios`
- `编排实例`：`/admin/ranges`

### 6.2 编排实例列表增加 `创建人`

## 7. 实例管理页面设计

### 7.1 页面定位

`实例管理` 页面专门用于：

1. 创建单个或多个 ECS 实例
2. 管理运行中的单实例
3. 查看已关闭的单实例历史
4. 执行重启 / VNC / 镜像打包等操作

它不是拓扑编排页，也不是实例详情页。

### 7.2 页面结构

页面采用与 `编排实例` 相同的列表型工作台风格：

1. 顶部列表标题
2. 搜索筛选
3. `实例列表 / 实例历史` 切换
4. 右上角 `创建实例`

### 7.3 实例列表字段

运行中实例列表字段固定为：

1. 实例名
2. 创建人
3. 镜像
4. 规格
5. 公网 IP
6. 状态
7. 创建时间
8. 到期时间
9. 操作

其中：

- `镜像` 展示平台收录镜像显示名
- `规格` 展示 `x 核 / y G`
- `公网 IP` 优先展示运行后回写的实例公网地址

### 7.4 实例历史字段

实例历史字段固定为：

1. 实例名
2. 创建人
3. 镜像
4. 规格
5. 公网 IP
6. 开启时间
7. 回收时间
8. 运行时长
9. 操作

历史页只保留查看型展示，不显示运行态操作。

### 7.5 操作列设计

运行中单实例的操作列使用一个 `更多操作` 菜单承载：

1. `关闭实例`
2. `重启实例`
3. `打开 VNC`
4. `打包为镜像`

说明：

- `关闭实例` 的语义是**销毁该单实例资源并沉淀到历史中**
- 第一阶段不在单实例页暴露“仅关机不销毁”的 ECS 停机动作，避免与“实例历史”语义冲突
- `打包为镜像` 成功后，镜像必须自动进入“平台收录镜像”

异常状态补充规则：

1. `create_failed`
   - 操作列提供 `重试创建`
   - 操作列提供 `删除记录`
2. `destroy_failed`
   - 操作列提供 `重试关闭`

### 7.6 空状态

空状态文案需要区分：

1. 当前没有单实例
2. 当前没有历史实例
3. 当前没有可选平台镜像

其中当平台镜像为空时：

- 需要明确提示用户先去 `镜像中心` 收录镜像，再回来创建实例

## 8. 创建实例弹窗设计

### 8.1 弹窗结构

创建实例弹窗风格参考用户提供的截图，但必须对齐当前平台后台风格，不照搬外部控制台视觉。

弹窗字段固定为：

1. `实例名`，必填
2. `主机名`，可选
3. `镜像`，必填，来自平台收录镜像
4. `CPU / 内存`，必填
5. `磁盘大小`，可选
6. `到期时间`，必填
7. `密码`，可选；不填则随机
8. `启动实例数量`，默认 `1`
9. `备注`，可选

不提供：

1. `源 IP`
2. `是否分配公网 IPv4`

公网 IP 固定默认为分配。

### 8.2 镜像字段交互

镜像字段使用可搜索选择器：

1. 只展示已启用的平台收录镜像
2. 展示镜像显示名
3. 提交时传递平台镜像资产 ID 及关联 image ID

### 8.3 规格字段交互

CPU / 内存 的交互与当前编排页 ECS 属性面板保持一致：

1. 用户输入 CPU
2. 用户输入内存
3. 前端调用现有规格可售校验接口
4. 如果默认可用区无精确可售规格，则在弹窗内联提示

规格策略固定为：

- 经济型规格优先

前端不让用户直接手填最终 `instanceType`。

### 8.4 数量字段交互

`启动实例数量` 默认值为 `1`。

当数量大于 `1` 时：

1. 前端仍只输入一个实例名前缀
2. 后端按两位序号自动展开最终实例名

例如：

- `web-lab` + `3`
- 生成：
  - `web-lab-01`
  - `web-lab-02`
  - `web-lab-03`

### 8.5 密码策略

密码字段规则固定为：

1. 用户填写则优先使用填写值
2. 用户不填写则由后端生成随机 ECS 密码

该逻辑与当前编排实例的 runtime credential 生成策略保持一致。

## 9. 数据模型设计

### 9.1 `RangeTemplate` 增加 `createdBy`

模板主表新增：

- `createdBy`

用途：

1. 支撑靶场列表的 `创建人` 字段
2. 为后续用户体系预留最基本的创建归属

### 9.2 `RangeInstance` 增加实例模式和单实例配置

`RangeInstance` 新增：

1. `instanceMode`
   - `range`
   - `single`
2. `singleInstanceConfig`
   - 单实例专用配置快照

`singleInstanceConfig` 至少保存：

1. `hostName`
2. `platformImageAssetId`
3. `imageId`
4. `imageDisplayName`
5. `cpu`
6. `memory`
7. `systemDiskSize`
8. `quantityIndex`
9. `baseName`
10. `remark`
11. `assignedVswitchId`

设计原因：

1. 单实例不依赖模板
2. 不能强行塞进“靶场模板”语义
3. 需要保存创建时的镜像与规格快照，供列表、历史与错误恢复使用

### 9.3 默认单实例网络表

新增单独表，例如：

- `SingleInstanceNetworkProfile`

用于保存默认网络：

1. `provider`
2. `regionId`
3. `zoneId`
4. `vpcId`
5. `vpcCidr`
6. `vswitchIds`
7. `vswitchCidrs`
8. `securityGroupId`
9. `securityGroupName`
10. `createdAt`
11. `updatedAt`

第一阶段唯一性范围固定为：

- `provider + regionId + zoneId`

在当前实现里，这已经等价于“当前云账号上下文”。

### 9.4 历史保留策略

单实例销毁后：

1. 实例记录保留
2. 任务记录保留
3. 镜像、规格、公网 IP 等展示快照尽量保留

这样实例历史才能完整展示。

## 10. 默认网络与交换机分配设计

### 10.1 默认网络创建时机

默认网络在**首次创建单实例**时检查和补齐：

1. 先读取 `SingleInstanceNetworkProfile`
2. 若存在则直接复用
3. 若不存在则自动创建默认网络资源并持久化

### 10.2 默认网络资源内容

自动创建的资源固定为：

1. 1 个 VPC
2. 3 个交换机
3. 1 个安全组
4. 安全组默认全开放

### 10.3 CIDR 分配策略

默认网络的 VPC CIDR 需要复用现有 `CidrPoolService` 选择一个不与活动编排实例冲突的网段。

在选定默认 VPC CIDR 后：

1. 系统按固定规则切出 3 个子网段
2. 这 3 个子网段分别对应 3 个交换机

第一阶段不开放人工配置。

### 10.4 交换机分配策略

系统根据当前活动单实例数量做轮转：

1. 活动单实例数 `mod 3`
2. 选择对应序号的交换机

这条规则要求：

1. 简单
2. 可解释
3. 不引入额外复杂调度器

## 11. API 与任务链路设计

### 11.1 单实例页面使用独立 API 路由

虽然底层复用 `RangeInstance`，但前端页面建议使用独立 API 路由，避免把 `编排实例` 和 `单实例` 混在一个控制器查询参数里。

建议新增：

1. `GET /admin/instances`
2. `POST /admin/instances/launch`
3. `POST /admin/instances/:id/destroy`
4. `POST /admin/instances/:id/retry`
5. `POST /admin/instances/:id/actions/:action`

### 11.2 单实例创建接口

`POST /admin/instances/launch`

请求体包含：

1. 实例名前缀
2. 主机名
3. 平台镜像资产 ID
4. CPU
5. 内存
6. 磁盘大小
7. 到期时间
8. 密码
9. 数量
10. 备注

后端行为：

1. 校验镜像必须存在且已启用
2. 校验 CPU / 内存合法
3. 校验到期时间有效
4. 校验默认网络是否存在，否则自动创建
5. 按数量展开实例名
6. 为每个实例创建 `RangeInstance(instanceMode = single)`
7. 为每个实例创建 `ProvisionJob(create)`
8. 返回创建结果

### 11.3 单实例销毁接口

`关闭实例` 对应：

- `POST /admin/instances/:id/destroy`

语义：

1. 走销毁任务
2. 成功后实例进入历史

### 11.4 单实例更多操作接口

`更多操作` 建议走实例级接口，而不是前端暴露 nodeId：

1. `POST /admin/instances/:id/actions/reboot`
2. `POST /admin/instances/:id/actions/open-vnc`
3. `POST /admin/instances/:id/actions/pack-image`

后端内部可复用现有节点动作服务，只是自动映射到该单实例唯一主机节点。

### 11.5 任务与状态

单实例继续复用现有任务类型：

1. `create`
2. `destroy`
3. `retry`

运行态操作：

1. `reboot`
2. `open-vnc`
3. `pack-image`

不新增单实例专属任务中心。

## 12. Provisioning 设计

### 12.1 单 ECS 模块继续复用

单实例继续复用：

- `infra/opentofu/modules/alicloud-vpc-single-ecs`

但需要扩展为支持：

1. 传入既有 `vpcId`
2. 传入既有 `vswitchId`
3. 传入既有 `securityGroupId`

当传入这些既有网络 ID 时：

1. 模块不再创建 VPC / 交换机 / 安全组
2. 只创建 ECS

### 12.2 默认公网 IP

单实例 provisioning 固定启用公网 IP 分配，不再做前端开关。

### 12.3 规格选择策略

单实例 provisioning 需要复用当前编排实例 ECS 的规格解析思路：

1. 用户输入 CPU / 内存
2. 前端预先做规格可售校验
3. worker 侧再次按默认地域 / 可用区解析最终可售规格
4. 经济型规格优先

### 12.4 打包镜像闭环

单实例 `打包为镜像` 的行为与当前编排实例节点一致：

1. 创建阿里云自定义镜像
2. 写入镜像快照
3. 自动收录到平台镜像目录

## 13. 兼容性与迁移

### 13.1 模板创建人回填

数据库迁移时：

1. `RangeTemplate.createdBy` 新增后
2. 历史模板统一回填为 `admin`

### 13.2 实例模式回填

数据库迁移时：

1. 现有全部实例默认回填为 `instanceMode = range`

### 13.3 单实例历史与旧页面隔离

新增 `实例管理` 页面只展示：

- `instanceMode = single`

`编排实例` 页面只展示：

- `instanceMode = range`

避免两类实例混在同一列表里。
