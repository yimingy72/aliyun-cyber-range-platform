# 镜像中心三层结构与平台镜像资产设计

日期：2026-07-06
最近更新：2026-07-06
状态：Active

## 当前状态快照

这份设计对应的主数据结构和前端信息架构已经进入落地阶段，当前仓库中已可见的状态为：

1. 镜像中心已切成 3 个 tab：`平台收录镜像`、`阿里云自定义镜像`、`阿里云公共镜像`
2. 平台镜像资产已作为独立语义层接入，并被 `靶场编排` 页 ECS 镜像选择器消费
3. 自定义镜像支持云端删除，平台收录镜像支持重命名、启停用、删除出目录
4. 镜像中心当前默认仍以系统基础配置中的默认地域作为自定义镜像查询地域

仍需继续细化的点：

- 更多与账号切换、地域切换相关的运营级体验
- 平台镜像资产在后续实例选型链路中的进一步约束校验

## 1. 背景

当前平台的镜像中心同时承载了两类不同语义的数据：

1. 阿里云侧实时同步回来的镜像快照
2. 平台内部真正可供“靶场编排”消费的镜像目录

目前实现中，这两层数据在前端页面里混合展示，且“收录到目录”的目标语义不够清晰。随着后续平台需要支持：

- 公共镜像查询
- 自定义镜像查询
- 平台内部镜像资产管理
- 编排页只从平台内部稳定镜像目录中选镜像

现有模型已经不足以表达完整业务边界，需要把“云端快照”和“平台镜像资产”明确拆开。

## 2. 本次目标

本次设计只解决镜像中心与镜像资产模型，不延伸到实例创建链路的其他改造。

目标如下：

1. 镜像中心前端改为 3 个 tab：
   - `平台收录镜像`
   - `阿里云自定义镜像`
   - `阿里云公共镜像`
2. 明确“收录到目录”的含义：
   - 从阿里云镜像快照生成平台镜像资产
3. `靶场编排` 页中的镜像下拉只消费 `平台收录镜像`
4. 平台镜像资产必须绑定阿里云账号
5. 平台镜像资产按账号隔离，后续切换账号时切换对应目录
6. `阿里云自定义镜像` 当前不支持切换地域，默认展示 `基础配置` 页中的默认地域
7. `平台收录镜像` 支持完整管理能力：
   - 编辑镜像名（展示名）
   - 启用 / 停用
   - 删除出目录（不删除云端镜像）
8. `阿里云自定义镜像` 支持删除云端镜像
9. 删除云端自定义镜像后，需要自动同步处理平台镜像资产

## 3. 非目标

本次不处理以下内容：

1. 不实现多地域切换 UI
2. 不实现公共镜像的云端删除
3. 不在本轮设计中改造实例创建逻辑
4. 不处理历史模板引用缺失镜像资产时的迁移脚本细节
5. 不在本轮内增加镜像标签、镜像分类、镜像用途等高级元数据

## 4. 当前问题

### 4.1 数据语义混乱

当前 Prisma 中已经存在：

- `CloudImageSnapshot`
- `ImageCatalogItem`

但当前前端页面没有把两层数据区别讲清楚，用户看到的是“同步结果”和“目录结果”混在一个页面里。

### 4.2 镜像中心和编排页的镜像来源不清晰

当前 `靶场编排` 页已经会消费目录数据，但从产品语义上没有明确说明“编排页只能选择平台确认收录后的镜像”。这会导致后续：

- 镜像目录不稳定
- 切账号后镜像混淆
- 页面认知成本高

### 4.3 缺少平台镜像资产层

如果继续直接复用现有 `ImageCatalogItem` 承载所有后续能力，会让“快照映射”和“平台资产管理”两种职责继续耦合。后续一旦加入：

- 重命名
- 启停用
- 账号切换
- 引用关系

就会越来越难维护。

## 5. 核心设计

### 5.1 三层数据模型

本次明确拆成三层：

1. `阿里云公共镜像快照`
2. `阿里云自定义镜像快照`
3. `平台镜像资产`

其中前两者本质上都属于 `CloudImageSnapshot`，只是 `scope` 不同：

- `public`
- `custom`

真正供平台消费的是第三层：`平台镜像资产`。

### 5.2 “收录到目录”的准确定义

“收录到目录”统一改名和理解为：

`将某个 CloudImageSnapshot 收录为 PlatformImageAsset`

也就是说：

- 云端快照只是候选数据
- 平台资产才是正式目录
- 编排页、镜像中心中的“平台收录镜像”都只看平台资产

### 5.3 平台镜像资产与阿里云账号绑定

平台镜像资产必须绑定当前阿里云账号身份。最少需要绑定：

- `provider`
- `accountUid`
- `accountScopeKey`
- `regionId`

设计目的：

1. 不同阿里云账号的自定义镜像目录不能混淆
2. 即使同一个 `imageId` 在不同账号中都存在，也应视为不同资产来源
3. 后续切换阿里云账号时，平台收录镜像能够自动切换到对应账号下的数据

### 5.4 默认地域策略

`阿里云自定义镜像` 页面当前不支持用户切换地域。

当前策略：

1. 读取 `基础配置` 页面里保存的默认地域
2. 仅查询并展示该地域下的自定义镜像
3. 平台镜像资产也默认以当前默认地域为归属维度

后续如要支持多地域切换，再单独扩展。

## 6. 数据模型设计

### 6.1 保留现有快照表

保留现有 `CloudImageSnapshot` 用作云端快照池。

职责：

- 记录阿里云镜像同步结果
- 提供公共镜像和自定义镜像列表
- 作为平台资产的收录来源

### 6.2 新增平台镜像资产表

新增独立表：`PlatformImageAsset`

建议字段：

- `id`
- `provider`
- `accountUid`
- `accountScopeKey`
- `regionId`
- `sourceScope`：`public | custom`
- `sourceSnapshotId`
- `imageId`
- `displayName`
- `enabled`
- `createdAt`
- `updatedAt`

补充说明：

1. `displayName`
   平台展示名，可编辑，不影响实际 `imageId`
2. `imageId`
   实际执行层使用的镜像 ID，不允许通过前端修改
3. `enabled`
   控制是否可在 `靶场编排` 中被选择
4. `sourceSnapshotId`
   记录来源，方便后续联动失效或回溯

### 6.3 唯一性约束

建议唯一约束：

- `provider + accountScopeKey + regionId + imageId`

含义：

同一个账号、同一个地域、同一个镜像 ID，只允许收录为一条平台镜像资产。

### 6.4 旧 `ImageCatalogItem` 的处理

本次采用“平台资产型”，因此 `ImageCatalogItem` 不再作为长期主模型继续扩展。

处理策略：

1. 新能力全部落到 `PlatformImageAsset`
2. 编排页后续切换为只读取 `PlatformImageAsset`
3. `ImageCatalogItem` 可保留作兼容过渡
4. 后续完成迁移后，再决定是否移除

本轮不强制删除旧表，但不再向其继续叠加新业务语义。

## 7. 前端设计

### 7.1 页面结构

镜像中心页面改为顶部 3 个 tab，视觉结构对齐 `靶场实例` 页面。

tab 顺序固定为：

1. `平台收录镜像`
2. `阿里云自定义镜像`
3. `阿里云公共镜像`

原因：

- 平台资产是平台内部的主工作面
- 公共镜像、自定义镜像是来源面

### 7.2 平台收录镜像页

主要展示 `PlatformImageAsset`。

支持操作：

1. 编辑镜像名
   - 只修改展示名
   - 不修改 `imageId`
2. 启用 / 停用
   - 停用后不再出现在编排页镜像下拉中
3. 删除出目录
   - 只删除平台资产
   - 不删除阿里云镜像

建议列表字段：

- 镜像名
- 镜像 ID
- 来源类型（公共 / 自定义）
- 地域
- 状态（启用 / 停用）
- 收录时间
- 操作

### 7.3 阿里云公共镜像页

主要展示 `CloudImageSnapshot(scope=public)`。

支持操作：

1. 同步镜像
2. 收录为平台镜像

不支持删除云端镜像。

建议列表字段：

- 镜像名
- 镜像 ID
- 平台 / 架构
- 可用状态
- 最近同步时间
- 操作

### 7.4 阿里云自定义镜像页

主要展示 `CloudImageSnapshot(scope=custom)`。

支持操作：

1. 同步镜像
2. 收录为平台镜像
3. 删除云端镜像

当前不支持切换地域，只展示基础配置中的默认地域结果。

建议列表字段：

- 镜像名
- 镜像 ID
- 架构
- 状态
- 最近同步时间
- 操作

### 7.5 分页

镜像中心三页都需要支持真实分页，而不是仅展示静态分页控件。

分页样式参考用户提供的样式：

- 页大小选择器
- 页码区
- 跳转页输入

优先支持服务端分页；如果当前后端返回规模较小，也可先落前端分页，但最终接口应预留服务端分页能力。

## 8. 后端接口设计

### 8.1 保留并继续使用的快照接口

保留：

- `GET /admin/image-catalog/public`
- `GET /admin/image-catalog/custom`
- `POST /admin/image-catalog/public/sync`
- `POST /admin/image-catalog/custom/sync`

但其语义应收敛为：

- 只服务阿里云快照页
- 返回快照数据为主

### 8.2 新增平台资产接口

新增建议接口：

- `GET /admin/platform-images`
- `POST /admin/platform-images`
- `PATCH /admin/platform-images/:id`
- `POST /admin/platform-images/:id/enable`
- `POST /admin/platform-images/:id/disable`
- `DELETE /admin/platform-images/:id`

接口职责：

1. `GET`
   获取当前账号、当前默认地域下的平台镜像资产
2. `POST`
   根据 `snapshotId` 收录新平台镜像资产
3. `PATCH`
   修改展示名
4. `enable / disable`
   切换是否可被编排选择
5. `DELETE`
   仅删除平台资产，不删云端镜像

### 8.3 自定义镜像删除接口

新增建议接口：

- `DELETE /admin/image-catalog/custom/:snapshotId`

职责：

1. 调用阿里云删除对应自定义镜像
2. 删除成功后，回写或失效本地快照
3. 同步处理对应的平台镜像资产

### 8.4 删除云端自定义镜像后的联动规则

当删除云端自定义镜像成功后：

1. 对应 `CloudImageSnapshot` 需要标记不可用，或在下一次同步中移除
2. 对应 `PlatformImageAsset` 不能继续处于可用状态
3. 默认联动策略：
   - 若存在对应平台镜像资产，则直接“移出目录”

选择“移出目录”而不是仅停用的原因：

- 该镜像已经在云端被删除
- 平台再保留目录意义不大
- 可以避免编排页中继续看到无效资产

## 9. 与靶场编排的关系

### 9.1 镜像来源切换

`靶场编排` 中 ECS 的镜像选择器必须切换为只读取 `平台收录镜像`。

即：

- 不直接读取公共镜像快照
- 不直接读取自定义镜像快照
- 不继续把“同步结果”直接暴露给编排页

### 9.2 编排存储内容

编排页在选择镜像后，仍应把以下值保存进模板：

- `platformImageAssetId`
- `imageId`
- `imageName/displayName`

这样即使后续展示名变化，也不会影响执行层；执行层仍然只依赖 `imageId`。

### 9.3 失效镜像处理

如果模板引用的 `PlatformImageAsset` 后续被停用或移出目录：

1. 旧模板数据不应被静默清空
2. 编排页打开时应提示“当前镜像已失效或已移出目录”
3. 用户需要重新选择可用镜像后再保存

本轮先在设计中明确该行为，具体 UI 呈现方式放到实现计划中细化。

## 10. 分页与查询策略

### 10.1 当前阶段

为了快速上线镜像中心 UI，本轮允许：

1. API 先返回完整列表
2. 前端实现真实分页切换与页大小控制

前提是：

- 分页控件必须真实可用
- 页面切换不能只是视觉装饰

### 10.2 后续扩展

后续如果公共镜像量很大，再把 `GET` 接口升级为：

- `page`
- `pageSize`
- `keyword`

并返回：

- `items`
- `total`
- `page`
- `pageSize`

本次设计为此预留空间，但不强制要求首轮就完成完整服务端分页。

## 11. 风险与约束

### 11.1 账号隔离风险

如果平台镜像资产不绑定账号，则切换阿里云账号后，自定义镜像目录会混淆，必须避免。

### 11.2 地域差异风险

当前自定义镜像默认只看基础配置中的默认地域。如果用户切换默认地域，镜像中心和平台目录应跟随新地域上下文变化。

因此平台镜像资产必须带 `regionId`。

### 11.3 历史数据兼容风险

已有模板可能仍然使用旧目录表或旧镜像字段。此次只定义新主路径，不在本轮设计中强制一次性完成所有历史迁移。

### 11.4 云端删除联动风险

删除云端自定义镜像后，如果平台资产仍残留，将导致编排页继续引用无效镜像，因此联动处理是强制要求，不是可选项。

## 12. 验收标准

满足以下条件即视为本轮设计目标完成：

1. 镜像中心前端可在 3 个 tab 间切换：
   - 平台收录镜像
   - 阿里云公共镜像
   - 阿里云自定义镜像
2. 平台收录镜像页可：
   - 编辑展示名
   - 启用 / 停用
   - 删除出目录
3. 阿里云公共镜像页可：
   - 同步
   - 收录为平台镜像
4. 阿里云自定义镜像页可：
   - 同步
   - 收录为平台镜像
   - 删除云端镜像
5. 删除云端自定义镜像后，相关平台镜像资产自动联动清理
6. 编排页镜像选择器只消费平台镜像资产
7. 平台镜像资产按账号 + 地域隔离
8. 自定义镜像当前默认只展示基础配置中的默认地域
9. 镜像中心分页控件真实可用

## 13. 实施建议

推荐按以下顺序落地：

1. 新增 `PlatformImageAsset` 数据模型与 Prisma 迁移
2. 新增平台资产接口
3. 镜像中心改为 3-tab 结构
4. 落平台镜像资产页的编辑 / 启停 / 删除出目录
5. 落自定义镜像删除云端接口与联动逻辑
6. 将编排页镜像来源切到平台镜像资产

这样能先建立稳定的数据语义，再做前端切换，避免 UI 先改完、数据层又重来一遍。
