# 实例详情页同步 Flow 拓扑画布设计

**日期：** 2026-07-29  
**分支：** `codex/instance-detail-flow-canvas`  
**状态：** 已确认

## 目标

将“实例详情”的拓扑工作区升级为与创建拓扑页同源的 Flow 画布。运行中的编排实例可完成节点、连线、交换机 NAT/ACL 和节点属性编辑，保存为实例草稿后再显式应用到该实例。历史实例仅可浏览。

本次同时提供“更新编排拓扑”操作：把已保存的实例草稿回写到来源模板的当前草稿版本。该操作不会自动发布模板，也不会改动已运行的其他实例。

## 范围

### 包含

- 使用共享 `TopologyFlowCanvas` 替换实例详情的旧 `TemplateCanvas`。
- 运行中实例支持新增资源、删除节点/连线、连线、拖动、属性编辑、自动布局、撤销/重做、缩放平移、全屏和按需小地图。
- 历史实例维持相同的浏览体验，但禁用一切拓扑变更、保存、应用和回写模板操作。
- 实例草稿保存、应用实例变更、回写来源模板三个彼此独立的状态转换。
- 客户端和服务端对图、拓扑规格、场景规格及运行规格的一致性校验。
- 桌面端工作台布局与全屏体验；不新增移动端专项优化。

### 不包含

- 从实例草稿自动发布模板到平台。
- 自动将模板变更推送到已运行实例。
- 将一个实例的修改同步到多个模板或其他实例。
- 绕过现有云资源变更任务、权限或确认机制。

## 体验与组件边界

### 共享画布

`TopologyFlowCanvas` 继续保持通用，只负责画布渲染和交互：

- 无限画布、选择/连线模式、资源面板、属性面板联动、小地图、全屏、自动布局、撤销重做和防重叠放置。
- 增加通用的 `edit` / `readonly` 能力模式。只读模式保留选择、平移、缩放、全屏和小地图，但禁用新增、删除、连线、拖动提交和快捷键修改。
- 增加通用全屏目标参数。创建页仍使用现有工作台容器；实例页传入自身的三栏容器，使资源面板、画布和属性面板共同进入全屏。
- 不引入实例 API、权限判断、草稿保存或云资源业务。

### 实例适配层

`range-instance-topology-workspace` 变为实例专用的受控适配层，向共享画布传入：

- 实例草稿的 `nodes`、`edges`、`viewport`、`selection`。
- 编辑回调、撤销/重做回调、布局回调和节点位置/视口提交回调。
- 当前实例是否可编辑，以及全屏三栏容器。
- 实例属性面板的运行中可编辑、历史只读状态。

`range-instance-detail-screen` 维护实例业务状态，不再让画布直接修改运行态快照：

- 图状态：`nodes`、`edges`、`viewport`。
- UI 状态：`selection`、`TopologyHistory`、脏状态、保存/应用/回写的异步状态。
- 服务端源状态：已保存实例草稿、运行态快照、来源模板修订号。

## 三层拓扑状态

| 层 | 存储对象 | 何时改变 | 影响范围 |
| --- | --- | --- | --- |
| 模板草稿 | 来源模板的当前草稿版本 | 用户确认“更新编排拓扑”后 | 后续从该模板启动的实例 |
| 实例草稿 | 编排实例的 `draftTopologyGraph` 及其编译规格 | 用户点击“保存草稿”后 | 仅当前编排实例，尚不影响云上 |
| 实例运行态 | 编排实例的运行态拓扑快照 | “应用变更”任务成功后 | 仅当前编排实例的云资源与运行态 |

页面初始化优先使用已保存的实例草稿；不存在实例草稿时才展示运行态快照。草稿中的画布视口一并保存并在刷新后恢复。

未保存的浏览器内编辑不写入 `localStorage`。实例草稿以服务端为唯一持久化来源，避免本地缓存覆盖其他操作者或服务端最新草稿。

## 操作流程

### 保存草稿

1. 用户编辑运行中实例的拓扑。
2. 页面只修改内存草稿和撤销历史，并显示“存在未保存变更”。
3. 用户点击“保存草稿”。
4. 客户端调用共享的纯编译器，对图进行结构校验，生成拓扑规格、场景模板规格和运行规格。
5. `PATCH /admin/ranges/:rangeId/draft` 原子保存图、视口和三份派生产物。
6. 成功后显示“草稿已保存，尚未应用”，运行态快照不变。

### 应用变更

1. 用户点击“应用变更”。
2. 若内存草稿未保存，先执行保存草稿；保存失败则停止。
3. 服务端再次复核已保存草稿和派生产物，再创建实例变更任务。
4. 任务只创建、修改或销毁当前编排实例对应的云资源。
5. 任务成功后更新当前实例的运行态快照；失败时保留实例草稿和精确失败原因，供用户修正后重试。

只有状态为 `running` 的实例可应用变更。

### 更新编排拓扑

1. 用户在已保存实例草稿的基础上点击“更新编排拓扑”。
2. 界面展示确认对话框，明确说明：将覆盖来源模板的当前草稿版本；不会自动发布；不会影响已运行实例。
3. 用户确认后，调用现有 `POST /admin/ranges/:rangeId/sync-template`，携带来源模板的期望修订号。
4. 服务端重新校验实例草稿，使用同一编译器重建派生产物，并原子更新来源模板的当前草稿版本与修订号。
5. 服务端返回更新后的模板修订。后续从该模板启动的私有实例使用此新草稿；已发布的公开版本仍保持不变，必须在模板页显式发布后才更新平台可见版本。

回写模板不创建云资源任务。只有运行中实例的已保存草稿可以回写；来源模板不存在、没有编辑权限、模板修订冲突或实例草稿未保存时，操作失败且模板不被修改。不得回退使用实例运行态快照覆盖模板。

## 校验与错误处理

客户端和服务端共享一套无副作用的拓扑草稿编译核心，确保创建页、实例草稿保存和模板回写的规则一致：

- 仅允许路由器、交换机、ECS 和合法的连接关系。
- 节点、边、NIC、交换机、DNAT、ACL 的引用必须完整且一致。
- 新增/删除连线时同步维护 NIC 与相关引用；删除节点时清理关联边、NIC、DNAT 和 ACL 引用。
- 至少存在一个唯一的 DNAT 目标 ECS 作为公网入口；无 DNAT 和多目标 DNAT 分别返回现有精确错误。
- DNAT 外部端口不可重复，端口范围、协议、ECS 网络归属和交换机引用必须合法。
- 图校验或编译失败时，不允许保存“新图 + 旧规格”，更不允许创建应用任务或回写模板。
- API 不信任客户端派生产物；保存、应用和回写都重新校验图与规格一致性。

操作反馈显示在各自按钮附近的轻量状态区域。失败时不清空当前图、视口、选择或撤销历史。

## 权限与并发

- 实例所有者与平台管理员可保存和应用自己有权访问的运行中实例草稿。
- “更新编排拓扑”额外要求调用者有来源模板的编辑权限；没有权限时返回拒绝，不提供覆盖入口。
- 保存实例草稿使用实例修订号进行乐观并发控制。
- 回写模板使用模板当前修订号进行乐观并发控制。模板在详情页加载后被其他人更新时，服务端返回冲突，用户需刷新并重新确认，不能静默覆盖。
- 历史实例不暴露任何变更入口，即使用户拥有来源模板编辑权限。

## 接口与数据变更

### 实例草稿

现有实例草稿保存接口扩展为持久化：

- `draftTopologyGraph.viewport`
- `draftTopologyGraph.nodes`
- `draftTopologyGraph.edges`
- 由同一图编译出的 `draftTopologySpec`
- `draftScenarioTemplateSpec`
- `draftCompiledProvisionSpec`

保存响应必须返回实例草稿修订和规范化后的图，供前端替换本地草稿。

### 模板回写

扩展现有接口：

```text
POST /admin/ranges/:rangeId/sync-template
```

请求携带：

- 来源模板的 `expectedTemplateRevision`；

实例详情查询响应额外返回来源模板当前修订号，供客户端在用户确认后作为 `expectedTemplateRevision` 传回。确认对话框是 Web 交互保护；服务端以调用者权限、运行中状态、已保存草稿和修订号作为最终约束。

响应返回：

- 更新后的模板 ID、草稿版本和修订号；
- 被保存的模板拓扑图与派生产物摘要。

## 验收与测试

### Web

- 运行中实例加载 Flow 画布，选择节点可打开属性面板。
- 新增资源不重叠；合法连线自动同步 NIC；删除节点清理关联引用。
- 节点移动、视口改变、撤销、重做和自动布局均进入实例草稿。
- 全屏模式仍显示资源面板和属性面板；小地图默认隐藏且可按需打开。
- 历史实例可平移缩放查看，但不能编辑、保存、应用或回写模板。
- 保存草稿成功后刷新页面，恢复服务端草稿和视口。
- 不合法图、DNAT 缺失/多目标、端口冲突不调用保存或应用接口。
- 应用变更先保存后发起任务；运行态仅在任务完成后更新。
- 回写模板需要确认，成功后只更新模板草稿，不改变已发布版本或其他运行实例。

### API

- 拒绝图与派生产物不一致、无效引用、无 DNAT、多 DNAT 目标与端口冲突的实例草稿。
- 拒绝对历史实例保存或应用变更。
- 应用任务仅操作指定实例，且仅从服务端验证通过的草稿创建。
- 模板回写要求来源模板编辑权限、已保存草稿和匹配的模板修订号。
- 模板修订冲突时返回冲突且不写入；回写成功后只更新当前草稿版本。

### 容器验证

在 Docker 容器中重建 `web`、`api`、`provisioner-worker` 与相关依赖镜像，并执行：

- Web 画布、实例详情和模板编辑器回归测试；
- API 实例草稿、应用变更和模板回写的定向 e2e 测试；
- 生产 Web/API 镜像健康检查。
