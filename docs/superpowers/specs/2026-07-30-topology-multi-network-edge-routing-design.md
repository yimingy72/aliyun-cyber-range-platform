# 多网卡拓扑连线可读性设计

## 状态

设计已确认，等待 Spec 审阅与实施计划。

## 背景

模板创建、模板编辑和编排实例详情页共用 React Flow 拓扑画布。当前手工边统一使用 `smoothstep` 路由，且每个节点的输入和输出都固定使用左右侧的单一中心句柄。

当一台 ECS 配置多张网卡并连接多个交换机时，多条边会在 ECS 前或交换机后汇聚为一段共同折线。虽然底层 `TemplateEdge` 关系正确，但画面上会误读为一条公共主干，无法一眼辨认 ECS 连接的是哪几个交换机。

## 目标

- 让同一 ECS 与多个交换机之间的每条连线在自动布局后都保持可辨识的独立路径。
- 不显示网卡名称或额外文字，不扩大节点卡片。
- 保留当前连线的选择、删除、撤销重做、保存草稿、检测保存和实例编辑行为。
- 在模板创建、模板编辑和编排实例详情页的同一画布实现中保持一致。

## 非目标

- 不修改 `TemplateEdge`、ECS 网卡、交换机、NAT、ACL 或后端拓扑 JSON 的语义和结构。
- 不新增可编辑的网卡端口、端口标签或端口级连线数据。
- 不改变自动布局的节点列、节点顺序或节点间距。
- 不处理移动端布局和手势。

## 方案选择

采用“分离端点的平滑曲线”：

1. React Flow 边类型由 `smoothstep` 改为原生 `bezier`。
2. 对于每个节点的入边和出边，分别计算无文字的端点序列。
3. 边连接到各自分配的端点，曲线直接从源节点到目标节点，不经过共享的直角汇流段。

该方案不需要自定义 SVG 路由器，也不改变领域模型。与保留折线并增加绕线路径相比，它在当前“路由器 -> 交换机 -> ECS”的横向布局中更紧凑，也最容易看清一台 ECS 与两个交换机的关系。

## 架构

### 端点分配

在 `topology-flow-adapter` 中根据节点与边生成临时的画布端点布局：

- 边的源端使用源节点右侧端点，目标端使用目标节点左侧端点。
- 每个节点的入边与出边独立分组；组内按“对端节点 ID、边 ID”排序，确保输入数组顺序变化、刷新和自动布局不会改变端点次序。
- 单条边继续使用边缘中心位置。
- 多条边在节点边缘的中间区域均匀排列，避开卡片圆角；端点以无文字小圆点呈现。
- 每条画布边携带唯一的 `sourceHandle` 和 `targetHandle`。这些字段只存在于 React Flow 适配结果，不写入草稿或后端。

`TopologyFlowNode` 接收端点布局并渲染对应的 React Flow `Handle`。非连线模式下，已使用端点仍可见但不可点击；进入连线模式后保留现有可连接能力，并提供居中的默认连接句柄，避免影响新增连线。

### 边渲染

`toFlowEdges` 输出 `bezier` 边并引用上述唯一端点。React Flow 根据真实端点坐标生成两端水平切向的平滑曲线：

- 两个交换机分别连接同一 ECS 时，曲线在 ECS 左侧落到不同的无文字端点。
- 不同来源的边不会再被 `smoothstep` 的中间折线合并为公共主干。
- 原有边 ID、选择状态、点击命中区和删除选择均由 React Flow 边实体保持。

### 交互与兼容

- `onConnect` 仍只消费 `source` 与 `target`，沿用现有连线校验、重复边处理和网卡同步逻辑；句柄 ID 不参与领域保存。
- 节点拖动、平移、缩放、适应视图和自动布局不改变端点排序，只改变曲线几何。
- 只有一条连接时视觉保持现状的中心进出，避免简单拓扑出现不必要的细节。
- 无效或缺失端点的边回退到默认中心句柄，确保旧拓扑或异常草稿仍可打开与编辑。

## 样式与可访问性

- 连接线沿用当前蓝色、选中青色、悬停和键盘焦点样式；仅路径类型从圆角折线变为平滑曲线。
- 已使用端点保持低干扰的小尺寸圆点，不出现网卡名称、编号或悬浮说明。
- 非连线模式下端点不接管指针事件，节点点击与画布平移保持原有行为。
- 连线模式下端点维持现有键盘与鼠标连接能力，并继续由现有的连线校验给出反馈。

## 异常处理

- 边的源或目标节点不存在时，适配器继续忽略该无效边，不产生端点。
- 节点只有一侧存在连接时，仅为该侧计算端点，另一侧仍保留默认连接句柄。
- 因旧缓存或临时状态导致句柄未就绪时，React Flow 以默认句柄渲染，不阻塞拓扑加载、草稿恢复或保存。

## 测试策略

先以失败测试定义以下行为：

- 适配层：双交换机连接同一 ECS 时，为两条边生成不同的源/目标句柄，并输出 `bezier` 类型。
- 适配层：打乱节点和边的输入顺序后，端点 ID 与端点顺序保持一致。
- 节点组件：多条已连接边渲染各自无文字端点；单条边仍使用中心端点；连线模式下默认连接句柄可用。
- 画布组件：所传 React Flow 边保留选择状态、端点引用和现有连接回调。
- 样式契约：曲线路径、已用端点及选中态样式存在，且非连线模式的端点不会拦截鼠标操作。

## 容器验证

实现完成后，重建 Web 镜像，并通过 Docker 容器执行相关 Vitest 和 Web 构建。使用已登录浏览器进行不保存的验收：

1. 为同一 ECS 添加两张分别连接不同交换机的网卡。
2. 点击自动布局，确认两条连线从不同端点独立进入 ECS，没有共同的折线主干。
3. 选中、删除、撤销和重做其中一条边，确认另一条边与端点保持正确。
4. 刷新页面，确认草稿缓存恢复后连线样式和节点关系不变。

验证不执行检测保存、发布、实例创建、应用变更或任何云资源操作。
