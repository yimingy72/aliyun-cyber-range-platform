# 拓扑编辑器状态提示位置设计

## 背景

创建拓扑页在“检测与保存”后将结果渲染在画布下方。检测失败时错误文本较长，会压缩编辑区域并与画布操作分离。用户确认将提示恢复到模板标题区域，并移除“已完成全部自动布局。”这一无须用户处理的成功提示。

## 目标

- 将拓扑编辑器的操作反馈固定到模板标题下方。
- 复用紧凑、低强调的小字状态样式，不占用画布底部。
- 保留检测、保存、发布、连线、删除和失败等需要用户了解的提示。
- 自动布局成功后不显示成功提示；自动布局失败仍显示失败原因。

## 交互与布局

标题工具栏左侧拆分为两行：

1. 第一行显示模板名称和发布状态标签。
2. 第二行仅在存在 `statusMessage` 时显示紧凑状态文字。

状态文字使用 `role="status"` 与 `aria-live="polite"`，以保持异步反馈可访问。桌面端状态文字保持单行截断，完整文本放入 `title` 属性，避免长检测错误拉高标题工具栏或侵占画布空间。操作按钮仍靠右对齐，不随状态文本移动。

不再在画布网格下方渲染独立状态段落，因此画布可占用原先被提示占据的可用高度。

## 状态语义

- 检测与保存：显示成功、校验失败或请求失败信息。
- 拓扑编辑：保留新增、删除、连线、撤销、重做等现有反馈。
- 自动布局：成功时清空当前状态文本，不展示“已完成全部自动布局。”；失败时显示“自动布局失败，请保留当前节点位置。”。

本次不改变拓扑数据、保存 API、检测逻辑、发布流程或移动端布局。

## 实现边界

- 修改 `template-editor-screen.tsx` 的标题栏标记与自动布局成功消息。
- 在 `app/globals.css` 为标题身份行和状态文字增加局部样式。
- 在 `template-editor-screen.test.tsx` 覆盖标题区状态提示、底部提示移除及自动布局无成功提示。

## 验证

- 触发检测失败后，提示在标题下方以小字显示，画布下方不出现状态文本。
- 触发自动布局成功后，节点位置更新且不显示成功提示。
- 触发自动布局异常后，标题区显示失败提示。
- Docker Web 构建和相关回归测试通过；重建并重启隔离环境 Web 容器。
