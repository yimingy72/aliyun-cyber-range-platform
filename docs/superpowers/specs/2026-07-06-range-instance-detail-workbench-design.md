# 靶场实例详情工作台与实例变更应用设计

日期：2026-07-06
状态：Draft

## 1. 背景

当前平台中的 `靶场实例` 页面已经具备：

1. 实例列表 / 实例历史切换
2. 创建、销毁、重试、删除失败实例等基础操作
3. 一个基础版的“实例详情”弹窗

但现有“实例详情”仍然停留在信息查看层：

- 只能看少量实例字段
- 不能完整查看实例拓扑
- 不能按节点查看详细配置
- 不能对运行中的实例做受控配置变更
- 模板页点击 `生成实例` 时仍然直接用默认实例名创建，缺少到期时间输入和生命周期控制

参考站点 `组网详情` 页面已经体现出更贴近运维工作台的形态：

- 顶部实例概览
- `节点目录 / 拓扑结构` 双视图
- 节点级运行操作
- 在拓扑中选中或右击节点后查看配置

本次设计目标是在平台内实现一版更完整、可持续扩展的“实例详情工作台”。

## 2. 本次目标

本次设计覆盖四个主目标：

1. 将模板页 `生成实例` 改为带弹窗确认的启动流程
2. 将 `靶场实例 -> 查看详情` 从弹窗升级为独立工作台页面
3. 为运行中的实例增加“实例级配置草稿 -> 手动应用变更”的能力
4. 将实例 `expiresAt` 打通为自动回收链路

## 3. 非目标

本次不处理以下内容：

1. 不开放实例详情页中的新增节点、删除节点、修改连线
2. 不把实例详情页做成和模板编排页完全等价的完整在线编排器
3. 不在本轮引入实例变更回滚能力
4. 不在本轮支持多人并发编辑同一实例的复杂协作机制
5. 不在本轮重做 `靶场实例` 页之外的整站信息架构

## 4. 核心设计结论

### 4.1 实例详情页采用独立工作台

新的“查看详情”不再保留为当前弹窗，而改为独立页面：

- 路由建议：`/admin/ranges/[rangeId]`

详情页定位：

- 既是实例查看页
- 也是实例运维与变更工作台

### 4.2 实例变更采用“草稿 -> 手动应用”模式

用户在详情页中的所有可编辑配置，先写入**实例级变更草稿**。

只有在用户明确点击 `应用变更` 后，后端才会：

1. 校验当前实例状态
2. 校验改动范围是否合法
3. 创建实例变更任务
4. 下发到当前运行实例

这样可以避免：

- 每改一个字段就立即变更云资源
- 误操作直接影响运行实例
- 模板配置与实例运行时配置语义混淆

### 4.3 只允许修改“已有节点属性”

在实例详情页中，拓扑结构只允许修改已有节点的配置属性。

明确限制：

- 允许修改：
  - ECS 规格
  - ECS 安全组
  - ECS 账号密码
  - ECS 网络相关字段
  - 交换机 ACL / NAT / DNAT 等配置
  - 路由器必要基础属性
- 不允许修改：
  - 新增节点
  - 删除节点
  - 修改节点连线
  - 改变拓扑结构本身

### 4.4 只有运行中实例允许应用变更

状态策略固定为：

- `running`
  - 可编辑
  - 可保存草稿
  - 可应用变更
  - 可执行主机操作
- `pending_create / creating / pending_destroy / destroying`
  - 只读
  - 不允许编辑和应用变更
- `create_failed / destroy_failed / destroyed`
  - 可查看历史配置
  - 不允许应用变更

## 5. 生成实例流程设计

### 5.1 模板页“生成实例”必须先弹窗确认

当前模板页中的 `生成实例` 按钮不再直接创建实例。

改造后流程：

1. 用户点击 `生成实例`
2. 弹出启动实例弹窗
3. 用户填写：
   - 实例名
   - 到期时间
4. 用户确认后，才真正创建实例并触发启动任务

### 5.2 到期时间字段语义

前端字段名称使用：

- `到期时间`

后端落库仍使用：

- `expiresAt`

规则：

1. 到期时间必填
2. 到期时间必须晚于当前时间
3. 到期后实例会自动进入回收流程

## 6. 实例详情页结构设计

### 6.1 顶部实例概览区

顶部概览区显示：

1. 实例名
2. 场景名称
3. 当前状态
4. 创建人
5. 创建时间
6. 公网 IP
7. 到期时间

可补充轻量提示：

- `将于 xxxx 自动回收`
- 或 `已到期，等待系统回收`

### 6.2 中部双视图工作区

详情页主体提供两个视图：

1. `节点目录`
2. `拓扑结构`

#### 节点目录视图

节点目录按卡片展示每个资源，字段固定为：

1. 节点图标
2. 节点名称
3. IP 地址
4. 规格信息
5. 节点类型
6. 账号
7. 密码
8. 复制按钮

主机类节点额外显示运行操作：

1. `关机`
2. `重启`
3. `打开VNC`
4. `更多`

`更多` 菜单下包含：

1. `重置`
2. `二次打包镜像`

其中 `二次打包镜像` 的业务定义为：

- 将当前实例对应主机的当前镜像打包为新镜像
- 保存为当前阿里云账号下的自定义镜像
- 同时收录到平台镜像目录

#### 拓扑结构视图

拓扑结构视图包含：

1. 中间大画布展示实例真实拓扑
2. 左侧或角落保留轻量图例
3. 点击节点后右侧出现属性面板

右侧属性面板复用当前模板编排器的布局风格，但要切换到实例语义：

- 不显示新增节点相关能力
- 不显示改连线相关能力
- 仅显示当前实例可编辑配置

### 6.3 详情页全局操作

详情页需要提供统一操作区，建议放在页面头部或画布右上角。

包含：

1. `保存变更草稿`
2. `应用变更`
3. `放弃未应用修改`

规则：

1. 运行中实例可用
2. 非运行中实例禁用
3. 页面存在未保存变更时，离开页面应提醒

## 7. 实例运行时配置模型

### 7.1 实例必须拥有独立运行时快照

实例一旦创建出来，就不能只继续依赖模板版本作为配置来源。

原因：

1. 模板后续可能继续修改
2. 实例详情页会形成自身运行时配置
3. 实例与模板后续会产生分叉

因此每个实例需要拥有自己的运行时快照。

### 7.2 运行时快照与草稿快照

建议在 `RangeInstance` 层新增两组语义：

#### 当前已应用运行时快照

- `runtimeTopologyGraph`
- `runtimeScenarioTemplateSpec`
- `runtimeCompiledProvisionSpec`

#### 当前未应用草稿

- `draftTopologyGraph`
- `draftScenarioTemplateSpec`
- `draftCompiledProvisionSpec`
- `draftUpdatedBy`
- `draftUpdatedAt`

语义区别：

- `runtime*` 表示当前实例已应用到运行态的配置
- `draft*` 表示用户在详情页中尚未应用的配置草稿

## 8. 后端 API 设计

### 8.1 启动实例接口

建议新增原子化启动接口：

- `POST /admin/ranges/launch`

请求体包含：

1. `templateId`
2. `name`
3. `expiresAt`
4. `triggeredBy`

后端行为：

1. 校验模板可启动
2. 复制模板当前有效版本为实例运行时快照
3. 创建实例记录
4. 创建 `create` 任务
5. 返回实例与任务信息

### 8.2 实例详情读取接口

继续使用：

- `GET /admin/ranges/:id`

但返回结构需要扩展，至少包含：

1. 实例概览字段
2. 当前已应用运行时快照
3. 当前草稿快照
4. 最近任务
5. 资源摘要

### 8.3 保存草稿接口

新增：

- `PATCH /admin/ranges/:id/draft`

作用：

- 仅更新实例级草稿
- 不触发真实云资源变更

### 8.4 放弃草稿接口

新增：

- `DELETE /admin/ranges/:id/draft`

作用：

- 清空未应用草稿
- 还原为当前运行时快照

### 8.5 应用变更接口

新增：

- `POST /admin/ranges/:id/apply`

行为：

1. 校验实例状态为 `running`
2. 校验草稿存在
3. 校验草稿只修改了已有节点属性
4. 编译草稿
5. 创建变更任务
6. 交由 worker 执行更新

## 9. Provision Job 设计

### 9.1 任务类型扩展

当前 `ProvisionJobType` 建议从：

- `create`
- `destroy`
- `retry`
- `refresh_status`

扩展为：

- `create`
- `update`
- `destroy`
- `retry`
- `refresh_status`

`update` 用于实例详情页中的配置应用。

### 9.2 自动回收不新增独立任务类型

自动回收建议继续复用 `destroy`。

差异只体现在：

- `triggeredBy = system:auto-expire`

这样可以减少任务体系复杂度，复用已有销毁链路和错误处理。

## 10. Worker 与自动回收设计

### 10.1 实例变更应用

worker 在处理 `update` 任务时：

1. 读取实例当前 workspace / state
2. 基于实例草稿重新渲染配置
3. 执行 update 对应的 `plan/apply`
4. 成功后：
   - 用 `draft*` 覆盖 `runtime*`
   - 清空草稿字段
   - 回写 `resourceSummary / accessEntry`
5. 失败后：
   - 保留草稿
   - 记录错误摘要

### 10.2 自动回收

建议由现有 worker 或同一后端定时任务扫描：

- `status = running`
- `expiresAt <= now`

命中后自动创建 destroy 任务并进入正常回收流程。

## 11. 首批可编辑字段范围

为了控制复杂度，实例详情页中的首批可编辑字段建议明确如下：

### ECS

1. 规格
2. 安全组
3. 账号
4. 密码
5. 必要网络配置

### 交换机

1. ACL
2. NAT
3. DNAT
4. 必要网段相关字段

### 路由器

1. 必要基础属性

不在首批范围内的字段保持只读显示。

## 12. 测试范围

### 前端

1. 模板页生成实例弹窗
2. 实例列表到详情页跳转
3. `节点目录 / 拓扑结构` 视图切换
4. 右侧属性面板只读/可编辑态
5. `保存草稿 / 放弃草稿 / 应用变更`
6. 非运行中实例的禁用态

### 后端

1. `launch` 是否原子创建实例与任务
2. `expiresAt` 是否正确落库
3. 详情接口是否返回 runtime/draft 两套数据
4. `apply` 是否只允许 `running`
5. `apply` 是否拦截增删节点和改连线
6. 自动回收是否创建 destroy 任务
7. `update` 成功/失败后的状态回写

### 容器态回归

所有涉及前端、后端、worker、OpenTofu 的变更都必须在 Docker 容器态验证。

建议至少覆盖一条端到端链路：

1. 模板页生成实例
2. 进入实例详情
3. 修改草稿
4. 应用变更
5. 自动回收或手动销毁

真实阿里云 smoke 仅允许受控临时资源，并在测试后立即销毁。

## 13. 风险与控制

### 13.1 模板语义与实例语义混淆

风险：

- 直接复用模板编排器容易把“模板配置”和“实例运行配置”混为一谈

控制：

- 实例详情只允许编辑已有节点属性
- 实例详情使用独立运行时快照与草稿快照

### 13.2 应用变更直接影响云资源

风险：

- 错误修改会直接打到运行实例

控制：

- 强制走 `草稿 -> 校验 -> 手动应用`

### 13.3 自动回收误触发

风险：

- 误删未到期实例

控制：

- 只扫描 `running && expiresAt <= now`
- 自动回收仍复用标准 destroy 任务链路

## 14. 推荐实施顺序

建议按以下顺序实施：

1. 生成实例弹窗 + `launch`
2. 实例详情独立页面骨架
3. runtime/draft 数据结构
4. 实例详情可编辑属性面板
5. `apply update` 任务链路
6. 自动回收
7. 主机类运行操作与二次打包镜像联通
