# 账单费用：按成功开通分组的费用明细

**日期：** 2026-07-21

**状态：** 已确认，待实现规划

**范围：** 管理端“账单费用”模块的费用明细数据与界面

## 目标

将费用明细从逐条阿里云账单改为按平台一次成功开通分组。管理员能够先看到某次平台开通的总费用，再展开查看其关联的 ECS、云盘、EIP、网络等资源费用。

父行展示实际开通成功的完成时间，取关联开通任务的 `finishedAt`。阿里云逐日账单的 `billingDate` 只作为子行“账期”显示，且仅显示日期；不再将日期格式化为虚假的 `08:00:00` 消费时间。

## 已确认的产品决策

- 父行以一次成功开通为锚点，默认折叠，按开通完成时间倒序排列。
- `instanceMode=range` 的父行名称为“开启靶场实例”。
- `instanceMode=single` 的父行名称为“开启编排实例”。一个批次内的每台编排实例以其成功开通任务为独立父行。
- “用户费用明细”与“平台公共费用明细”合并为一个“费用明细”面板，通过“用户费用 / 平台公共费用”切换。
- 用户费用仍由现有用户列表筛选；未选择用户时显示引导文案。平台公共费用不受用户选择影响。
- 前端删除“资源类型汇总”区块；后端 `summary.resourceTypeTotals` 数据和既有汇总接口保持兼容。
- 现有 CSV 导出维持原始账单项粒度，本次不改变导出格式。

## 方案选择

采用运行时关联查询，不新增“开通费用事件”持久化表。现有费用台账已保存 `rangeInstanceId`、`singleInstanceBatchId`、`sourceProvisionJobId` 和 `billingStartAt`，资源账单已保存 `matchedLedgerId`；通过这些关联可重建开通分组。

该方案避免冗余存储和数据迁移，并仍以 `ProvisionJob.finishedAt` 作为权威的开通完成时间。

## 数据规则

### 关联与分组

1. 在查询窗口内先按现有条件获取原始费用项：用户视图限定 `billingScope=user` 与 `ownerUserId`，平台视图限定 `billingScope=platform`。
2. 对每个费用项，经 `matchedLedgerId` 查询费用台账，再用 `sourceProvisionJobId` 查询开通任务与 `rangeInstanceId` 查询实例。
3. 仅当任务状态为 `succeeded` 且有 `finishedAt` 时，将费用项放入开通分组；父行键为 `sourceProvisionJobId`。
4. 实例模式为 `range` 时标记为 `range_launch` 并显示“开启靶场实例”；模式为 `single` 时标记为 `single_launch` 并显示“开启编排实例”。
5. 父行金额为该分组在当前账期筛选范围内的子项金额之和；子项金额保留原始金额和币种。
6. 某次开通早于筛选窗口、但在窗口内仍有账单时，父行仍显示真实的历史开通完成时间。这说明费用的来源，不改变账期筛选语义。

### 台账写入与重试

- 资源首次由成功的创建或创建重试开通时，费用台账写入该次成功任务的 `sourceProvisionJobId` 与完成时刻的 `billingStartAt`。
- 对实例更新任务，既有资源台账不得覆写首次开通的 `sourceProvisionJobId` 或 `billingStartAt`；新增资源才关联本次成功任务。
- 创建失败、已取消或没有 `finishedAt` 的任务绝不作为父行。

### 无法关联的历史费用

没有 `matchedLedgerId`、台账没有来源任务、来源任务已缺失，或任务不是成功开通任务的费用，归入 `unmatched` 父行。该父行名称为“未关联平台启动的费用”，展示账期范围和费用合计，不展示伪造的具体时刻；展开后仍可审计每条原始资源账单。

该降级规则保留历史费用可见性，避免把公共费用或旧账单错误归属到某一次开通。

## API 与类型

新增两类分组查询，替代页面对原始明细列表的直接渲染：

```text
GET /admin/billing/users/:userId/groups?startAt&endAt&limit
GET /admin/billing/platform/groups?startAt&endAt&limit
```

`limit` 表示父分组数量，而非子账单条数。每个分组携带完整子项，使页面不会在展开后静默遗漏资源费用。

响应形态：

```ts
type BillingLaunchGroup = {
  id: string;
  kind: 'range_launch' | 'single_launch' | 'unmatched';
  title: '开启靶场实例' | '开启编排实例' | '未关联平台启动的费用';
  completedAt: string | null;
  billingPeriodStart: string;
  billingPeriodEnd: string;
  instance: { id: string; name: string; batchId: string | null } | null;
  resourceCount: number;
  pretaxAmount: number;
  currency: string;
  items: BillingLineItem[];
};
```

返回列表按 `completedAt` 倒序；`unmatched` 组按其最新账期倒序并排在可关联组之后。既有原始明细接口和导出接口不移除，以避免破坏现有 API 使用方。

## 界面与交互

“费用明细”面板取代原先分别显示的“用户费用明细”和“平台公共费用明细”：

- 顶部为分段按钮：`用户费用`、`平台公共费用`。
- 用户费用视图显示当前选中用户的分组；平台公共费用直接显示平台分组。
- 每个父行展示展开按钮、真实开通完成时间、开通类型、实例/靶场名称、资源数量和费用合计。
- 展开子项显示资源类型与 ID、费用项目、账期（日期）、金额与币种。子项不显示“消费时间”。
- 保留现有账单总览、待确认归属、用户列表、导出和立即同步功能。
- 删除前端资源类型汇总卡片及其对应展示样式；总览接口仍照常请求或可保留其兼容字段，不以此作为页面依赖。
- 分组列表的加载、空态、鉴权失败和同步后重新获取，沿用当前页面的行为；切换视图只加载该视图所需数据。

## 错误处理与兼容性

- 任何单条费用项关联失败时，不能使整页失败；该项进入 `unmatched` 分组。
- 无选择用户、无账单、无平台公共费用均有明确空态。
- 旧的原始明细和 CSV API 保持响应兼容。新的分组 API 仅供更新后的页面使用。
- 时间统一以服务端 ISO 时间传输，管理端按现有管理员时区格式化。父行只格式化 `completedAt`，子行只格式化账期日期。

## 测试与容器验证

新增或扩展 API 服务测试，覆盖：

1. 成功靶场实例按任务 `finishedAt` 分组，并汇总 ECS、云盘、EIP 等子项。
2. 成功编排实例显示“开启编排实例”，并使用各自成功任务作为父行。
3. 更新任务不会替换既有资源的首次开通任务和开始时间。
4. 未关联、失败或未完成任务的费用进入 `unmatched`，不显示伪造时刻。
5. 用户与平台范围严格隔离，日期窗口仅限制账单项而非篡改父行开通时间。
6. 管理端能切换两个费用视图、展开资源子项、显示完成时间而不是 `08:00:00`，并且不再渲染资源类型汇总。

所有实现后的测试、镜像构建和回归验证均通过 Docker Compose 容器完成，不使用本地开发进程替代容器验证。

## 非目标

- 不修改阿里云原始账单同步语义或追溯原始账单到小时级消费时间。
- 不回填或猜测旧账单缺失的开通关联。
- 不改变费用分摊、异常归属规则或 CSV 结构。
