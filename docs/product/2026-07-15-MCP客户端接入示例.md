# 平台 MCP 客户端接入手册

本文说明如何将阿里云综合靶场竞赛平台接入 Codex、Claude Code 或其他支持远程 MCP 的客户端。适用于平台部署运维者、MCP 客户端使用者和集成开发者。

平台 MCP Gateway 使用 **Streamable HTTP**，不是 stdio 服务。连接、权限和运行状态均以当前容器环境为准。

## 1. 连接信息

| 项目 | 本地默认值 | 说明 |
| --- | --- | --- |
| MCP 地址 | `http://127.0.0.1:8787/mcp` | 仅接受 `POST` 请求。 |
| 健康检查 | `http://127.0.0.1:8787/healthz` | 接受 `GET` 请求，无需认证。 |
| Web 后台 | `http://127.0.0.1:3000/admin/login` | 用于平台管理与浏览器登录。 |
| OIDC issuer | `http://127.0.0.1:8080/realms/cyber-range` | 本地 Keycloak 默认 issuer。 |
| 入站 token audience | `mcp-gateway` | 必须与部署时的 `MCP_OIDC_AUDIENCE` 一致。 |

远程部署时，替换为 MCP 客户端可访问的 HTTPS 地址。不要把 `127.0.0.1` 配给另一台机器上的客户端。

## 2. 三分钟快速连接

### 2.1 启动并检查平台

```bash
pnpm compose:up

curl -fsS http://127.0.0.1:8787/healthz
```

预期返回：

```json
{"ok":true}
```

### 2.2 获取 OIDC access token

使用你的组织 OIDC 流程获取 access token。该 token 必须：

- 来自 `OIDC_ISSUER` 配置的 issuer；
- 未过期且可通过 issuer 的 JWKS 验签；
- audience 包含 `MCP_OIDC_AUDIENCE`，本地默认是 `mcp-gateway`；
- 其 subject 已关联一个启用的平台用户。

将 token 放在当前终端的环境变量中，而不是写入仓库或客户端共享配置：

```bash
export ALIYUN_CYBER_RANGE_MCP_TOKEN='<oidc-access-token>'
```

本地受控联调可用 compose smoke 验证服务账号链路：

```bash
pnpm compose:smoke:mcp
```

该 smoke 仅验证本地平台与 MCP 协议连通性；不要把开发 smoke 的 client secret、用户密码或 access token 复制到生产环境。

### 2.3 配置客户端

所有客户端使用以下共同信息：

```text
URL:     http://127.0.0.1:8787/mcp
Header:  Authorization: Bearer <oidc-access-token>
```

首次连接建议只调用只读工具，例如 `range_template_list`、`platform_image_list` 或 `single_instance_list`。

## 3. 客户端示例

### Codex

在 `~/.codex/config.toml` 中使用环境变量保存短期 token：

```toml
[mcp_servers.aliyun-cyber-range-platform]
url = "http://127.0.0.1:8787/mcp"
bearer_token_env_var = "ALIYUN_CYBER_RANGE_MCP_TOKEN"
```

也可在启动 Codex 的终端中添加：

```bash
codex mcp add aliyun-cyber-range-platform \
  --url http://127.0.0.1:8787/mcp \
  --bearer-token-env-var ALIYUN_CYBER_RANGE_MCP_TOKEN
```

### Claude Code 或通用远程 MCP 客户端

客户端配置格式会有所差异，但需要传递同一 URL 与 Authorization header。例如：

```json
{
  "mcpServers": {
    "aliyun-cyber-range-platform": {
      "transport": {
        "type": "http",
        "url": "http://127.0.0.1:8787/mcp",
        "headers": {
          "Authorization": "Bearer <oidc-access-token>"
        }
      }
    }
  }
}
```

请使用所选 MCP 客户端的官方配置格式；上例仅说明必要连接字段。

### 原始 HTTP 验证

先检查服务，而不是手写业务 JSON-RPC 请求：

```bash
curl -fsS http://127.0.0.1:8787/healthz
```

需要验证 MCP 协议时，使用项目提供的官方 SDK smoke：

```bash
MCP_URL=http://127.0.0.1:8787/mcp \
MCP_BEARER_TOKEN="$ALIYUN_CYBER_RANGE_MCP_TOKEN" \
pnpm --filter @aliyun-cyber-range/mcp smoke:http
```

## 4. 认证与授权流程

```text
MCP 客户端
  └─ Bearer OIDC access token ──> MCP Gateway
       ├─ 验证 issuer / 签名 / 有效期 / audience
       └─ Token Exchange ──> platform-api token ──> 平台 API
                                                    └─ scope、角色与资源归属校验
```

Gateway 不接受旧的平台浏览器 session token。正常生产接入应使用 OIDC Bearer access token。`MCP_STATIC_BEARER_TOKEN` 是受控本地 stub / smoke 的例外，不是生产认证方案。

权限有三个层次：

1. **MCP tool scope**：决定 token 是否能看到或调用某个工具。
2. **平台角色**：管理员额外具备用户管理与基础配置等权限。
3. **资源归属**：即使工具可调用，平台仍会限制用户访问或操作不属于自己的资源。

创建、销毁、重启、重试、打包镜像、修改用户或云配置等操作具有实际影响。Agent 应先说明目标与影响范围，客户端应要求用户确认；平台会按现有操作控制与审计规则处理请求。

## 6. 部署配置要点

部署 MCP 时应区分对外地址与容器内部地址：

| 配置 | 用途 |
| --- | --- |
| `MCP_PUBLIC_URL` | 部署配置中声明的公开 `/mcp` 地址；应与客户端实际连接的地址保持一致。 |
| `OIDC_ISSUER` | token 中的公开 issuer，必须可被浏览器和 MCP 客户端识别。 |
| `OIDC_JWKS_URL` | Gateway 获取签名密钥的地址；Compose 中通常是 `http://keycloak:8080/.../certs`。 |
| `OIDC_TOKEN_ENDPOINT` | Gateway 进行 Token Exchange 的地址；Compose 中通常是 `http://keycloak:8080/.../token`。 |
| `MCP_OIDC_CLIENT_ID` / `MCP_OIDC_CLIENT_SECRET` | Gateway 的 confidential client 配置。 |
| `PLATFORM_API_AUDIENCE` | 下游平台 API token 的 audience，默认 `platform-api`。 |

生产环境必须使用 HTTPS、真实 OIDC issuer 与独立 secret；不要沿用 `.env.example` 的开发默认值。完整部署步骤见：[当前系统部署说明](../../deploy/current-system/README.md)。

## 7. 常见问题

| 现象 | 检查方向 |
| --- | --- |
| `401 Missing or invalid platform token` | 检查 Bearer header、issuer、token 过期时间、audience 和平台用户是否启用。 |
| `405` | `/mcp` 只接受 `POST`；健康检查使用 `GET /healthz`。 |
| `500 OIDC token exchange failed` | 检查 Gateway 的 `OIDC_TOKEN_ENDPOINT`、MCP confidential client 和下游 audience。 |
| 客户端无法连接本地服务 | 确认客户端和平台在同一台主机；跨主机时使用公开 HTTPS 地址，不要使用 `127.0.0.1`。 |
| 工具不可见或资源访问失败 | 分别检查 tool scope、平台角色和资源 owner / visibility。 |

```text
涉及创建、销毁、重启、重试、打包镜像、用户或云配置变更时，先说明工具、目标与影响范围，并等待用户确认。

```
