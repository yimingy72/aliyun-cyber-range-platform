# 平台 MCP 对外接入手册

本文是综合靶场竞赛平台 MCP Server 的对外接入手册，适合直接发给：

- Codex 使用方
- Claude Code 使用方
- 需要通过 OpenAI / MCP SDK 集成平台能力的开发同学

本文覆盖：

- 平台 MCP 的认证方式
- MCP 客户端配置方式
- 当前全部 tool list
- 每个工具的用途说明
- 当前权限模型与已验证结论
- 审计与日志说明
- 推荐给 agent 的提示词

本文给出三类接入方式：

1. Codex / 支持远程 MCP URL 的客户端
2. OpenAI Responses API
3. 通用 MCP SDK / 原始 HTTP JSON-RPC

适用目标服务：

- MCP URL：`http://127.0.0.1:8787/mcp`
- Health URL：`http://127.0.0.1:8787/healthz`

## 0. 三分钟快速接入

如果你只想先接通，再慢慢看细节，按下面做即可。

### 0.1 启动平台

```bash
pnpm compose:up
```

### 0.2 获取 token

开发联调可直接使用：

```bash
curl -sS http://127.0.0.1:8080/realms/cyber-range/protocol/openid-connect/token \
  -H 'content-type: application/x-www-form-urlencoded' \
  --data-urlencode 'grant_type=client_credentials' \
  --data-urlencode 'client_id=mcp-smoke-sa' \
  --data-urlencode 'client_secret=mcp-smoke-secret'
```

取返回中的 `access_token`。

### 0.3 配置 MCP Client

最小配置：

```json
{
  "server_label": "aliyun-cyber-range-platform",
  "server_url": "http://127.0.0.1:8787/mcp",
  "headers": {
    "Authorization": "Bearer <oidc-access-token>"
  }
}
```

### 0.4 先测一个只读工具

建议先测：

- `range_template_list`
- `platform_image_list`
- `single_instance_list`

如果这三个能调通，说明你的认证、MCP URL、基础工具调用链路都已经正常。

## 1. 前置条件

### 1.0 接入方须知

接入前建议先明确这几个事实：

- 这是 **远程 HTTP MCP Server**，不是本地 stdio MCP
- 客户端需要自己配置 MCP URL 和认证 header
- 当前正式认证方式是 **OIDC access token**，不是平台旧 session
- MCP 本身不负责弹浏览器登录；你需要先拿到 token，再把 token 放进 MCP 配置
- 开发 smoke 可用 `mcp-smoke-sa / mcp-smoke-secret`，真实使用应改为真实平台用户 token

### 1.1 启动平台与 MCP

```bash
pnpm compose:up
```

或只做 MCP 联调：

```bash
MCP_SMOKE_SKIP_UP=1 pnpm compose:smoke:mcp
```

### 1.2 获取 OIDC access token

MCP 入站认证现在要求 **OIDC access token**，`aud` 需要包含 `mcp-gateway`。

开发环境推荐直接复用 compose smoke 的 service-account client：

```bash
curl -sS http://127.0.0.1:8080/realms/cyber-range/protocol/openid-connect/token \
  -H 'content-type: application/x-www-form-urlencoded' \
  --data-urlencode 'grant_type=client_credentials' \
  --data-urlencode 'client_id=mcp-smoke-sa' \
  --data-urlencode 'client_secret=mcp-smoke-secret'
```

如果你要模拟“真实用户登录后把用户 token 交给 MCP”，则应使用平台浏览器登录对应的 OIDC access token，而不是上面的 smoke service-account token。

返回示例里使用 `access_token`：

```json
{
  "access_token": "<oidc-access-token>",
  "token_type": "Bearer",
  "expires_in": 600
}
```

后续把 `token` 放到：

```text
Authorization: Bearer <oidc-access-token>
```

## 2. Codex / 远程 MCP 客户端示例

不同客户端的 UI 和配置文件格式可能不同，但核心字段通常只有这几个：

- server label / name
- MCP URL
- Authorization header
- 可选的 tool allowlist
- 可选的 approval policy

### 2.1 推荐填写值

- 名称：`aliyun-cyber-range-platform`
- URL：`http://127.0.0.1:8787/mcp`
- Header：`Authorization: Bearer <oidc-access-token>`

### 2.2 Codex 可直接照抄的配置结构

如果你的 Codex 支持“自定义远程 MCP server JSON 配置”，可以按下面的结构填写：

```json
{
  "server_label": "aliyun-cyber-range-platform",
  "server_url": "http://127.0.0.1:8787/mcp",
  "headers": {
    "Authorization": "Bearer <oidc-access-token>"
  }
}
```

### 2.3 Claude Code / 其他远程 MCP 客户端示例

如果客户端接受的是 `mcpServers` 风格配置，可以按这个思路填：

```json
{
  "mcpServers": {
    "aliyun-cyber-range-platform": {
      "transport": {
        "type": "http",
        "url": "http://127.0.0.1:8787/mcp",
        "headers": {
          "Authorization": "Bearer <oidc-access-token>"
        }
      }
    }
  }
}
```

### 2.4 建议的最小只读模式

`allowed_tools` / `allowedTools` 不是必填项。默认建议先不写，直接让平台自身权限控制生效。

如果你想在客户端侧额外加一层白名单，再使用下面这种只读限制写法：

如果你只是先验证连通性，建议先只开放只读工具：

```json
{
  "server_label": "aliyun-cyber-range-platform-readonly",
  "server_url": "http://127.0.0.1:8787/mcp",
  "headers": {
    "Authorization": "Bearer <oidc-access-token>"
  },
  "allowed_tools": [
    "range_template_list",
    "range_template_get",
    "platform_image_list",
    "range_instance_list",
    "range_instance_get",
    "range_instance_get_access",
    "single_instance_list",
    "single_instance_get",
    "single_instance_get_access",
    "provision_job_get"
  ]
}
```

### 2.5 建议给 agent 的提示词

```text

优先先做查询，再做变更。
涉及创建、销毁、重启、打包镜像等写操作前，先说明将调用的工具名和目标实例。
如果只需要查看信息，优先使用只读工具。
```

### 2.6 当前 MCP 工具清单

当前平台 MCP 已开放的工具如下。

#### 模板

- `range_template_list`：查询模板列表
- `range_template_get`：查询模板详情

#### 镜像

- `platform_image_list`：查询平台镜像 / 我的镜像

#### 综合靶场实例

- `range_instance_list`：查询综合靶场实例列表
- `range_instance_get`：查询综合靶场实例详情
- `range_instance_get_access`：查询综合靶场访问信息
- `range_instance_launch`：从模板启动综合靶场实例
- `range_instance_destroy`：销毁综合靶场实例

说明：当前 **不开放综合靶场内部单个 ECS 节点的开机、关机、重启等节点级操作**，只开放综合靶场整体启动与整体销毁。

#### 单实例

- `single_instance_list`：查询单实例 / 批次列表
- `single_instance_get`：查询单实例详情
- `single_instance_get_access`：查询单实例访问信息（IP、账号密码等）
- `single_instance_batch_launch`：批量创建单实例
- `single_instance_destroy`：销毁单个单实例
- `single_instance_batch_destroy`：批量销毁单实例批次
- `single_instance_retry`：重试失败任务
- `single_instance_reboot`：重启单实例
- `single_instance_open_vnc`：打开单实例 VNC
- `single_instance_pack_image`：将单实例打包为镜像

#### 任务

- `provision_job_get`：查询任务 / 作业详情

### 2.7 每个工具建议的 agent 调用意图

- `range_template_list`：当用户说“看看有哪些模板”“列出模板”“查综合靶场模板”
- `range_template_get`：当用户说“看这个模板详情”“给我模板的具体信息”
- `platform_image_list`：当用户说“看看有哪些镜像”“查镜像列表”
- `range_instance_list`：当用户说“看看我的综合靶场”“列出综合靶场实例”
- `range_instance_get`：当用户说“看这个综合靶场详情”
- `range_instance_get_access`：当用户说“给我这个综合靶场的访问信息 / IP / 凭据”
- `range_instance_launch`：当用户说“用这个模板启动一个综合靶场”
- `range_instance_destroy`：当用户说“销毁这个综合靶场”
- `single_instance_list`：当用户说“看看我的单实例”“列出靶机”
- `single_instance_get`：当用户说“看这个单实例详情”
- `single_instance_get_access`：当用户说“给我这个靶机的 IP / 账号密码”
- `single_instance_batch_launch`：当用户说“批量创建若干台靶机”
- `single_instance_destroy`：当用户说“销毁这台靶机”
- `single_instance_batch_destroy`：当用户说“把这一批靶机全部销毁”
- `single_instance_retry`：当用户说“重试这个失败任务”
- `single_instance_reboot`：当用户说“重启这台靶机”
- `single_instance_open_vnc`：当用户说“打开这个靶机的 VNC”
- `single_instance_pack_image`：当用户说“把这台靶机打包成镜像”
- `provision_job_get`：当用户说“看这个任务状态 / 作业状态 / 失败原因”

### 2.8 MCP 权限模型

当前平台 MCP 采用两层权限控制：

1. **MCP 工具层 scope 控制**：决定某个 token 是否允许调用某类工具。
2. **平台 API 资源归属控制**：决定调用后是否真的能访问 / 控制目标资源。

当前这批已开放工具，本质上是平台用户的“自助能力”，因此：

- 当前 `admin` 与普通 `user` **看到的 MCP 工具列表一致**
- 但普通用户不能越权访问或控制他人的资源
- 真正的限制目前主要落在**资源归属校验**，例如 `ownerUserId` / `createdBy` 检查

### 2.9 已实测的权限结论

以下结论基于容器态黑盒验证：

#### 普通用户对他人单实例

- `single_instance_get`：可调用，但返回 `null`
- `single_instance_get_access`：拒绝，返回 `Single instance not found`
- `single_instance_open_vnc`：拒绝，返回 `Range instance access denied`
- `single_instance_retry`：拒绝，返回 `Single instance access denied`
- `single_instance_reboot`：拒绝，返回 `Range instance access denied`
- `single_instance_pack_image`：拒绝，返回 `Range instance access denied`
- `single_instance_destroy`：拒绝，返回 `Single instance access denied`

#### 综合靶场实例

- 当前环境下这轮验证时没有活动中的综合靶场实例
- 因此 `range_instance_get` / `range_instance_get_access` / `range_instance_destroy` 还需要在存在活动综合靶场实例时补一轮回归

### 2.10 审计与日志说明

- MCP 调用最终仍然走平台已有的后端接口
- 因此会沿用当前平台已有的操作审计 / 历史记录体系
- 获取账号密码和 VNC **不要求二次确认，也不额外记录具体敏感内容本身**
- 其他创建、销毁、重启、重试、打包镜像等操作，仍按平台现有审计方式记录

### 2.11 给 Codex / Claude Code 的推荐提示词

```text
你可以使用 aliyun-cyber-range-platform MCP 来操作综合靶场竞赛平台。

工具使用原则：
1. 优先查询，再做变更。
2. 当用户要查看模板、镜像、实例、作业状态时，优先使用 list/get 类只读工具。
3. 当用户明确要求启动、销毁、重启、重试、打包镜像时，再调用对应写工具。
4. 调用写工具前，先用一句话说明你将调用哪个工具、目标资源是什么。
5. 如果用户只是要连接信息，优先使用 get_access 或 open_vnc，不要做额外控制操作。
6. 如果返回 access denied / not found，不要反复重试，应直接告知用户当前身份无权访问该资源。

常见映射：
- 查模板 -> range_template_list / range_template_get
- 查镜像 -> platform_image_list
- 启动综合靶场 -> range_instance_launch
- 销毁综合靶场 -> range_instance_destroy
- 查单实例 -> single_instance_list / single_instance_get
- 获取单实例连接信息 -> single_instance_get_access
- 打开单实例 VNC -> single_instance_open_vnc
- 重启单实例 -> single_instance_reboot
- 销毁单实例 -> single_instance_destroy
- 打包镜像 -> single_instance_pack_image
- 查看任务状态 -> provision_job_get
```

## 3. OpenAI Responses API 示例

如果你不是在 Codex UI 里接，而是在自己的 OpenAI 应用里接远程 MCP，可以把 MCP server 作为 `tools` 之一。

```bash
curl https://api.openai.com/v1/responses \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $OPENAI_API_KEY" \
  -d '{
    "model": "gpt-4.1",
    "input": "列出当前可用的综合靶场模板，并告诉我每个模板的 id。",
    "tools": [
      {
        "type": "mcp",
        "server_label": "aliyun-cyber-range-platform",
        "server_url": "http://127.0.0.1:8787/mcp",
        "headers": {
          "Authorization": "Bearer <oidc-access-token>"
        },
        "allowed_tools": [
          "range_template_list",
          "range_template_get"
        ],
        "require_approval": "never"
      }
    ]
  }'
```

如果你要让模型可以启动或销毁实例，把 `allowed_tools` 扩大即可；建议仍然显式列工具，不建议一开始就全放开。

## 3.1 认证边界说明

- 开发 smoke：默认用 `mcp-smoke-sa / mcp-smoke-secret` 走 `client_credentials`
- 人工真实使用：应使用用户在浏览器登录平台后获得的 OIDC access token
- MCP 不再接受平台旧 session token
- `MCP_STATIC_BEARER_TOKEN` 只保留给本地 stub / 过渡 smoke，不是正式接入方式

## 4. 通用 Node.js MCP SDK 客户端示例

```ts
import { Client } from '@modelcontextprotocol/sdk/client/index.js';
import { StreamableHTTPClientTransport } from '@modelcontextprotocol/sdk/client/streamableHttp.js';

const token = '<oidc-access-token>';
const client = new Client({ name: 'demo-client', version: '1.0.0' });
const transport = new StreamableHTTPClientTransport(new URL('http://127.0.0.1:8787/mcp'), {
  requestInit: {
    headers: {
      Authorization: `Bearer ${token}`,
    },
  },
});

await client.connect(transport);

const tools = await client.listTools();
console.log(tools.tools.map((tool) => tool.name));

const result = await client.callTool({
  name: 'range_template_list',
  arguments: {
    view: 'platform',
  },
});

console.log(result.structuredContent ?? result.content);

await transport.close();
await client.close();
```

## 6. 常见接入建议

### 6.1 先只读后写入

第一次接 agent，建议先只给：

- `range_template_list`
- `range_template_get`
- `platform_image_list`
- `range_instance_list`
- `range_instance_get`
- `single_instance_list`
- `single_instance_get`
- `provision_job_get`

### 6.2 写操作建议按工具白名单开放

建议分批放开：

第一批：

- `range_instance_launch`
- `single_instance_batch_launch`

第二批：

- `range_instance_destroy`
- `single_instance_destroy`
- `single_instance_batch_destroy`

第三批：

- `single_instance_retry`
- `single_instance_reboot`
- `single_instance_pack_image`
- `single_instance_open_vnc`

### 6.3 VNC 和凭据类工具

这类工具会返回敏感访问数据，建议只给受信 agent，并单独放白名单：

- `range_instance_get_access`
- `single_instance_get_access`
- `single_instance_open_vnc`
