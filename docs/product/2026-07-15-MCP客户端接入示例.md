# 平台 MCP 客户端接入手册

本文说明如何将阿里云、腾讯云综合靶场平台接入 Codex、Claude Code 或其他支持远程 MCP 的客户端。适用于平台部署运维者、MCP 客户端使用者和集成开发者。

平台 MCP Gateway 使用 **Streamable HTTP**，不是 stdio 服务。连接、权限和运行状态均以当前容器环境为准。

## 1. 连接信息

| 项目 | 本地默认值 | 说明 |
| --- | --- | --- |
| MCP 地址 | `http://127.0.0.1:8787/mcp` | 仅接受 `POST` 请求。 |
| 健康检查 | `http://127.0.0.1:8787/healthz` | 接受 `GET` 请求，无需认证。 |
| Web 后台 | `http://127.0.0.1:3000/admin/login` | 用于平台管理与浏览器登录。 |
| OIDC issuer | `http://127.0.0.1:8080/realms/cyber-range` | 本地 Keycloak 默认 issuer。 |
| 入站 token audience | `mcp-gateway` | 必须与部署时的 `MCP_OIDC_AUDIENCE` 一致。 |

远程部署时，替换为 MCP 客户端可访问的 HTTPS 地址。不要把 `127.0.0.1` 配给另一台机器上的客户端。

## 2. 三分钟快速连接

### 2.1 启动并检查平台

```bash
pnpm compose:up

curl -fsS http://127.0.0.1:8787/healthz
```

预期返回：

```json
{"ok":true}
```

### 2.2 获取 OIDC access token

使用你的组织 OIDC 流程获取 access token。该 token 必须：

- 来自 `OIDC_ISSUER` 配置的 issuer；
- 未过期且可通过 issuer 的 JWKS 验签；
- audience 包含 `MCP_OIDC_AUDIENCE`，本地默认是 `mcp-gateway`；
- 其 subject 已关联一个启用的平台用户。

将 token 放在当前终端的环境变量中，而不是写入仓库或客户端共享配置：

```bash
export ALIYUN_CYBER_RANGE_MCP_TOKEN='<oidc-access-token>'
```

本地受控联调可用 compose smoke 验证服务账号链路：

```bash
pnpm compose:smoke:mcp
```

该 smoke 仅验证本地平台与 MCP 协议连通性；不要把开发 smoke 的 client secret、用户密码或 access token 复制到生产环境。

### 2.3 配置客户端

所有客户端使用以下共同信息：

```text
URL:     http://127.0.0.1:8787/mcp
Header:  Authorization: Bearer <oidc-access-token>
```

首次连接建议只调用只读工具，例如 `range_template_list`、`platform_image_list` 或 `single_instance_list`。

## 3. 客户端示例

### Codex

在 `~/.codex/config.toml` 中使用环境变量保存短期 token：

```toml
[mcp_servers.aliyun-cyber-range-platform]
url = "http://127.0.0.1:8787/mcp"
bearer_token_env_var = "ALIYUN_CYBER_RANGE_MCP_TOKEN"
```

也可在启动 Codex 的终端中添加：

```bash
codex mcp add aliyun-cyber-range-platform \
  --url http://127.0.0.1:8787/mcp \
  --bearer-token-env-var ALIYUN_CYBER_RANGE_MCP_TOKEN
```

### Claude Code 或通用远程 MCP 客户端

客户端配置格式会有所差异，但需要传递同一 URL 与 Authorization header。例如：

```json
{
  "mcpServers": {
    "aliyun-cyber-range-platform": {
      "transport": {
        "type": "http",
        "url": "http://127.0.0.1:8787/mcp",
        "headers": {
          "Authorization": "Bearer <oidc-access-token>"
        }
      }
    }
  }
}
```

请使用所选 MCP 客户端的官方配置格式；上例仅说明必要连接字段。

### 原始 HTTP 验证

先检查服务，而不是手写业务 JSON-RPC 请求：

```bash
curl -fsS http://127.0.0.1:8787/healthz
```

需要验证 MCP 协议时，使用项目提供的官方 SDK smoke：

```bash
MCP_URL=http://mcp:8787/mcp \
MCP_BEARER_TOKEN="$ALIYUN_CYBER_RANGE_MCP_TOKEN" \
docker compose run --rm --no-deps -e MCP_URL -e MCP_BEARER_TOKEN mcp pnpm --filter @aliyun-cyber-range/mcp smoke:http
```

## 4. 认证与授权流程

```text
MCP 客户端
  └─ Bearer OIDC access token ──> MCP Gateway
       ├─ 验证 issuer / 签名 / 有效期 / audience
       └─ Token Exchange ──> platform-api token ──> 平台 API
                                                    └─ scope、角色与资源归属校验
```

Gateway 不接受平台浏览器 session token、静态 Bearer 或共用平台 API token。全部环境使用 OIDC Bearer access token 和 Token Exchange，保持同一 subject。

权限有三个层次：

1. **MCP tool scope**：决定 token 是否能看到或调用某个工具。
2. **平台角色**：管理员额外具备用户管理与基础配置等权限。
3. **资源归属**：即使工具可调用，平台仍会限制用户访问或操作不属于自己的资源。

创建、销毁、重启、重试、打包镜像、修改用户或云配置须属于用户已授权的目标和影响范围。授权持续有效，受控测试无需每一步重新询问。收到 `CONFIRMATION_REQUIRED` 时核对服务端摘要，在已有授权内用相同业务参数、确认 ID 和要求的稳定幂等键完成二阶段；超出原范围才补充确认。

## 5. 工具发现与业务合同

连接后通过 MCP SDK `listTools()` 获取当前用户可见工具及 `inputSchema`、`outputSchema`、`annotations`。兼容只有身份 scope 的旧 OAuth token；声明业务 scope 的 token 使用其与当前平台角色权限的交集，未知 scope 不授予权限。不同 scope、角色和部署版本下集合不同，不依赖固定工具数。所有业务工具顶层参数严格按 schema 传入，未知顶层参数会被拒绝。拓扑节点兼容扩展字段；实际执行规格由服务端重新编译核对，不接受调用方提供的派生部署配置。

| 分类 | 维护位置 |
|---|---|
| 平台镜像、云目录、标签、导入 | [镜像中心](../../skills/references/products/image-center.md) |
| 独立实例、批次、共享网络 | [实例管理](../../skills/references/products/instance-management.md) |
| 模板查询、创建、拓扑与发布 | [靶场编排](../../skills/references/products/range-authoring.md) |
| 运行拓扑、节点控制、DNS、回收 | [编排实例](../../skills/references/products/range-instances.md) |
| 空间内用户与权限 | [用户管理](../../skills/references/products/user-management.md) |
| 官方账单、同步、导出、待核对来源 | [账单费用](../../skills/references/products/billing.md) |
| 云账号绑定、显式工作空间选择 | [基础配置](../../skills/references/products/settings.md) |

运行拓扑编辑按保存草稿 → 预览准确版本 → 应用原版本与 preview token 执行；预览是配置差异，不是 OpenTofu 实际 plan。另存使用稳定幂等键新建私有模板，保留来源模板。DNS 使用独立 `dns` 字段，内部设置脚本不回写用户启动脚本；核验失败不自动重建。费用查询返回已同步官方金额与现有 `provisional`/待核对字段，不提供尚未实施的“创建即生成账单行”状态模型。

工具结果使用 `structuredContent.result`。`isError: true` 且 `result.error` 表示失败或服务端确认挑战，符合 schema 不表示操作成功。异步 receipt 只表示受理；从返回的 `jobId`/`provisionJobId`/`lastJobId` 取得准确 ID，再用 `provision_job_get({ provisionJobId: id })` 追踪。写入超时先查询原资源和作业，不能更换幂等键盲目重建。

访问凭据、临时 VNC 和凭据 CSV 需要明确请求与专用 scope；VNC 工具会签发临时访问票，并非无副作用的普通详情查询。不要传播敏感返回。

### 工作空间选择

用 `cloud_workspace_list` 定位所需厂商、主账号和准确空间 ID。可通过每次连接请求的 `x-cloud-workspace-id` 固定空间；不传该头时使用用户默认空间。`cloud_workspace_switch` 只改变默认选择，固定请求头保持原空间。不同厂商账号的镜像、模板、实例、用户和费用 ID 不可混用；后台作业始终使用受理时冻结账号。删除账号绑定不删除云资源或审计历史，未回收来源会阻止删除。

## 6. 部署配置要点

部署 MCP 时应区分对外地址与容器内部地址：

| 配置 | 用途 |
| --- | --- |
| `MCP_PUBLIC_URL` | 客户端公开 `/mcp` 地址，纳入精确 Host/Origin 允许列表。 |
| `MCP_ALLOWED_HOSTS` / `MCP_ALLOWED_ORIGINS` | 额外允许的 Host 与 Origin，逗号分隔、精确匹配，无通配 CORS。 |
| `OIDC_ISSUER` | token 中的公开 issuer，必须可被浏览器和 MCP 客户端识别。 |
| `OIDC_JWKS_URL` | Gateway 获取签名密钥的地址；Compose 中通常是 `http://keycloak:8080/.../certs`。 |
| `OIDC_TOKEN_ENDPOINT` | Gateway 进行 Token Exchange 的地址；Compose 中通常是 `http://keycloak:8080/.../token`。 |
| `MCP_OIDC_CLIENT_ID` / `MCP_OIDC_CLIENT_SECRET` | Gateway 的 confidential client 配置。 |
| `PLATFORM_API_AUDIENCE` | 下游平台 API token 的 audience，默认 `platform-api`。 |

生产环境必须使用 HTTPS、真实 OIDC issuer 与独立 secret；不要沿用 `.env.example` 的开发默认值。完整部署步骤见：[当前系统部署说明](../../deploy/current-system/README.md)。

### 6.1 云账号与镜像导入 Bucket

`cloud_account_bind` 由平台超管在明确厂商、地域、可用区及真实凭据下绑定或编辑账号，支持可选 `imageImportBucket`；保存不自动切换空间。兼容 `cloud_config_update` 只接收 schema 中的默认地域、可用区和凭据，**不接受 `imageImportBucket`**。

阿里云配置已有 OSS Bucket 不会将其费用自动纳入平台，也不证明平台专属使用；上传是否可用以服务端验证状态为准。腾讯云导入由平台维护专属 COS 创建来源链。MCP 不提供二进制上传或任意 Bucket 策略写入工具；通过 Web 上传后可查询导入任务。

### 6.2 代理与浏览器请求

Host/Origin 默认仅允许精确本机 loopback 和配置的公开 URL。容器 SDK 访问 `http://mcp:8787/mcp` 时，须配置 `MCP_ALLOWED_HOSTS=mcp:8787`（当前 Compose 已显式配置）。反向代理必须按真实访问地址配置允许列表；Gateway 不依据任意转发 Host 扩大信任范围，不开启通配 CORS。客户端发送 Origin 时须精确匹配 `scheme://host:port`；无 Origin 的 SDK 请求仍须通过 Host 和 OIDC 校验。

## 7. 常见问题

| 现象 | 检查方向 |
| --- | --- |
| `401 Missing or invalid platform token` | 检查 Bearer header、issuer、token 过期时间、audience 和平台用户是否启用。 |
| `405` | `/mcp` 只接受 `POST`；健康检查使用 `GET /healthz`。 |
| `500 OIDC token exchange failed` | 检查 Gateway 的 `OIDC_TOKEN_ENDPOINT`、MCP confidential client 和下游 audience。 |
| 客户端无法连接本地服务 | 确认客户端和平台在同一台主机；跨主机时使用公开 HTTPS 地址，不要使用 `127.0.0.1`。 |
| 工具不可见或资源访问失败 | 分别检查 tool scope、平台角色和资源 owner / visibility。 |

```text
不要输出或持久化密码、access token、SSH/VNC 地址或凭据 CSV 的敏感内容。
```
