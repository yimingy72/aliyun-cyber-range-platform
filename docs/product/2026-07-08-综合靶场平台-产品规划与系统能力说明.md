### 当前已确认的产品事实

1. 支持 `admin / user` 两类账号，统一 OIDC（Keycloak）登录
2. 普通用户可使用平台镜像和平台拓扑，默认不能维护他人资源
3. **实例管理**已独立成页：批量创建、历史、到期销毁、VNC、打包镜像、凭据 CSV
4. **编排实例详情工作台**已具备拓扑、节点目录、节点启停/重启/VNC/打包、访问入口、draft 保存与 apply
5. **账单费用**已支持 BSS 同步、用户/平台归属分组、异常列表与 CSV 导出
6. **镜像中心**支持平台资产、云目录同步、个人/平台可见性、标签与 OSS 导入任务
7. **MCP Gateway** 以 OIDC + Token Exchange 暴露平台工具面（写操作含确认、幂等、审计）
8. 拓扑编辑器持续打磨 Flow 画布（多网络边、端口、布局、全屏工作区）

## 1. 项目背景

综合靶场平台面向公司部门内部的网络安全靶机开发、靶场管理和资源治理场景，目标是在阿里云环境中提供一套可在线编排、可实例化启动、可统一管理、可自动销毁的企业网络型靶场平台。

主要业务诉求：

- 部门内部网络安全靶机开发
- 靶场拓扑在线编排与模板沉淀
- 镜像、靶机、实例等资源统一管理
- 不同员工的资源使用与费用归属追踪
- 通过 Agent / MCP 安全地自动化操作平台

要解决的核心问题：

- 传统靶场依赖人工创建云资源，效率低、复用性差
- 拓扑长期依赖文档或脚本，缺少统一编排界面
- 实例启动、销毁、回收、失败重试缺少统一入口
- 镜像、规格、网络策略缺少平台化治理
- 员工维度费用与资源归属缺少可审计视图

## 2. 产品目标

1. 提供可视化靶场拓扑在线编排能力
2. 将拓扑编译为可执行的云资源描述（`scenario-runtime` → OpenTofu）
3. 在 Docker 容器内完成阿里云资源创建、更新与销毁
4. 提供模板、编排实例、单实例、镜像、账单、用户与基础配置的后台能力
5. 提供受控 MCP 接入，使自动化客户端与 Web 共用同一套权限与业务边界
6. 在不引入选手前台 / 判题体系的前提下，成为部门内部统一的云上靶机开发工作台

## 3. 目标用户

- 部门内部网络安全靶机开发人员
- 部门内部靶场管理员
- 部门内部云资源运维与治理人员
- 受授权的自动化 Agent 操作者（通过 MCP）

当前定位为部门内部系统，**不面向选手侧、普通租户侧或公共展示侧**。

## 4. 当前开发进度概述

平台已从「固定示例靶场」演进为完整的平台化执行模式：

```text
在线拓扑编排
  → 模板草稿 / 检测保存 / 发布
  → 生成编排实例或单实例
  → ProvisionJob + provisioner-worker
  → OpenTofu（或 dry-run）
  → 阿里云资源 + 运行态回写 + 账单归属
```

### 4.1 总体进度判断

| 阶段 | 状态 | 说明 |
| --- | --- | --- |
| 第一阶段：平台底座 | **已完成** | Web / API / Worker / Postgres / OpenTofu / 容器部署 |
| 第二阶段：运行态与资产治理 | **主体已完成** | 实例详情工作台、节点运维、镜像中心、单实例、规格调度 |
| 第三阶段：多账号与成本治理 | **主体已完成** | 用户归属、可见性、账单同步与归属、OIDC、MCP 操作控制 |
| 持续打磨 | **进行中** | 拓扑画布 UX、并发 apply 保护、UI 一致性、账单归因边界 |

### 4.2 当前阶段结论

平台主业务闭环已可用，后续重点是体验与边界打磨，而不是从零补齐「能不能用」。
验证默认走 Docker 容器；真实云 smoke 仅在授权下使用最小资源并立即销毁。

### 4.3 下一阶段建议

- 拓扑 Flow 画布与多网络连线体验继续收敛
- 账单归属边界与异常费用可读性继续增强
- 员工配额 / 趋势分析（在已有归属台账之上）
- 离线部署镜像包按当前版本整理
- 多云仅作长期预留，不作为近期交付

## 6. 当前系统架构概览

```text
管理员 Web ───────┐
                  ├── API ── PostgreSQL
MCP 客户端 ── MCP ┘    │
       │          │    └── ProvisionJob ── provisioner-worker ── OpenTofu / 阿里云
       └── Keycloak ─── OIDC 验证与 Token Exchange
```

### 6.1 Web 管理后台

- 路径：`apps/web`
- 技术栈：Next.js
- 导航：镜像中心、实例管理、靶场编排、编排实例、用户管理、账单费用、基础配置

### 6.2 API 后端

- 路径：`apps/api`
- 技术栈：NestJS
- 职责：模板、实例、镜像、账单、用户、系统配置；编译入队；OIDC 鉴权；操作控制

核心领域服务（CodeGraph）：

- `RangeTemplatesService`：模板 CRUD、检测保存、发布校验
- `RangeInstancesService`：编排实例启动、draft/apply、销毁、访问
- `RangeInstanceNodeActionsService`：节点启停/重启/VNC/打包
- `SingleInstancesService`：单实例批次与生命周期
- `BillingService` / `BillingSyncService`：费用查询与 BSS 同步
- `ImageCatalogService` / `ImageImportsService`：镜像目录与导入
- `ProvisioningWorkerService`：认领并执行 `ProvisionJob`

### 6.3 Provisioner Worker

- 入口：`apps/api/src/worker-main.ts`
- 职责：在容器中执行 OpenTofu `init / plan / apply / destroy`，回写状态与输出
- 模式：`RANGE_PROVISIONER_MODE=opentofu | dry-run`

### 6.4 共享包

| 包 | 职责 |
| --- | --- |
| `packages/database` | Prisma 模型与迁移 |
| `packages/scenario-runtime` | 拓扑图 → 场景规格 → 编译 provision 规格 |
| `packages/iac-runner` | OpenTofu 进程封装 |
| `packages/platform-api-client` | MCP 等客户端共用的 API 客户端 |

### 6.5 IaC 与云资源

- `infra/opentofu/modules/alicloud-enterprise-range`：综合靶场
- `infra/opentofu/modules/alicloud-vpc-single-ecs` / `alicloud-single-instance-network`：单实例相关

### 6.6 身份与 MCP

- `infra/keycloak`：Realm、主题、Token Exchange
- `apps/mcp`：Streamable HTTP MCP；生产用 OIDC Bearer；静态 token 仅本地 smoke

### 6.7 关键数据实体

- `RangeTemplate` / `RangeTemplateVersion`：蓝图与草稿/发布版本
- `RangeInstance`：`range` 与 `single` 两种模式
- `ProvisionJob`：异步开通任务
- `PlatformImageAsset` / `ImageImportJob`：镜像资产与导入
- `PlatformUser` + 资源 `ownerUserId` / `visibility`
- 账单台账与归属表（用户 / 平台 scope）
- `OperationConfirmation` / `IdempotentOperation` / `OperationAuditEvent`：MCP 操作控制

## 8. 已打通的关键业务链路

### 8.1 综合靶场主链路

1. 用户 OIDC 登录
2. 管理员配置云账号与默认地域
3. 在靶场编排创建/编辑拓扑并检测保存
4. 发布模板（或使用已发布平台模板）
5. 生成编排实例并写入 ProvisionJob
6. Worker 执行 OpenTofu，回写状态与访问信息
7. 详情页运维节点或 apply 拓扑变更
8. 到期回收或手动销毁；账单同步可见费用

### 8.2 单实例链路

1. 镜像中心选择平台镜像
2. 规格校验通过后批量创建
3. 跟踪 job / 实例状态
4. 使用、导出凭据、打包镜像或销毁

### 8.3 Agent 链路

1. 客户端持有 OIDC access token 调用 `POST /mcp`
2. Gateway 交换为平台 API 身份
3. 按 scope 与确认策略执行工具
4. 与 Web 共用同一套资源与审计

## 9. 当前能力边界

仍然成立的边界：

- 仅阿里云；不做多云真实编排
- 网络模型为固定主 VPC + 附加 CIDR，不是任意多 VPC 自由拓扑
- 账单是平台归属审计，不是财务结算系统
- MCP 不能替代浏览器完成镜像二进制直传
- 真实 `opentofu` 模式会产生计费资源，流程演练应使用 `dry-run`
- 选手前台、判题、积分不在范围

体验层仍在增强（不阻断主闭环）：

- 复杂多网卡拓扑的画布边路由与布局
- 高并发 apply 时的用户可感知状态
- 账单异常行的解释与运营文案
