## 1. 项目背景

综合靶场平台面向公司部门内部的网络安全靶机开发、靶场管理和资源治理场景，目标是在阿里云环境中提供一套可在线编排、可实例化启动、可统一管理、可自动销毁的企业网络型靶场平台，并逐步沉淀为部门内部统一的网络安全靶机开发系统。

项目当前主要面向以下业务诉求：

- 部门内部网络安全靶机开发
- 靶场拓扑在线编排与模板沉淀
- 镜像、靶机、实例等资源统一管理
- 不同员工的资源使用情况统计与追踪

项目要解决的核心问题包括：

- 传统靶场依赖人工创建云资源，效率低、复用性差
- 靶场拓扑长期依赖文档或脚本维护，缺少统一的编排界面
- 实例启动、销毁、回收、失败重试缺少统一入口
- 镜像、规格、网络、安全策略等关键资源缺少平台化治理能力
- 镜像、靶机、模板等资产缺少统一管理与复用体系
- 员工维度资源使用情况缺少统一统计视图

## 2. 产品目标

平台当前阶段的产品目标如下：

1. 提供可视化靶场拓扑在线编排能力
2. 将拓扑编排结果自动编译为可执行的云资源描述
3. 基于 Docker 容器内的 OpenTofu 执行链路完成阿里云资源创建与销毁
4. 提供模板、实例、镜像、基础配置等后台管理能力
5. 逐步补齐单实例靶机启动、镜像制作、资源管理与统计能力
6. 为后续实例运维能力和镜像资产治理打下统一基础

## 3. 目标用户

当前平台的核心用户为：

- 部门内部网络安全靶机开发人员
- 部门内部靶场管理员
- 部门内部云资源运维与治理人员

当前阶段平台定位为部门内部使用系统，暂不面向选手侧、普通租户侧或公共展示侧开放。

## 6. 当前系统架构概览

当前系统由以下几个核心部分组成：

### 6.1 Web 管理后台

- 路径：`apps/web`
- 技术栈：Next.js
- 职责：管理员登录、靶场编排、靶场实例、镜像中心、基础配置等页面交互

### 6.2 API 后端

- 路径：`apps/api`
- 技术栈：NestJS
- 职责：模板、实例、镜像、系统配置等接口；拓扑编译、任务入队、状态回写

### 6.3 Provisioner Worker

- 路径：`apps/api/src/worker-main.ts`
- 职责：认领 `ProvisionJob`，在容器中执行 OpenTofu `init / plan / apply / destroy`

### 6.4 数据库层

- 路径：`packages/database`
- 技术栈：Prisma + PostgreSQL
- 职责：保存模板版本、实例记录、镜像资产、任务状态、运行时凭据等数据

### 6.5 IaC 与云资源执行层

- 路径：`infra/opentofu/modules/alicloud-enterprise-range`
- 职责：接收平台编译后的资源描述，驱动阿里云 Provider 创建与销毁资源

## 8. 当前已打通的关键业务链路

当前已打通的主链路如下：

1. 管理员登录后台
2. 配置阿里云基础参数
3. 在靶场编排页创建拓扑模板
4. 保存草稿 / 发布编排 / 检测拓扑
5. 基于模板生成靶场实例
6. API 创建实例记录并写入 Provision Job
7. Provisioner Worker 在 Docker 容器内执行 OpenTofu
8. 阿里云资源创建完成后回写实例状态与资源摘要
9. 支持实例销毁、失败重试、自动到期回收

## 9. 当前能力边界

虽然主链路已经建立，但当前系统仍存在以下边界：

- 实例详情页还未完全达到目标中的深度运维工作台形态
- 实时规格校验与 CPU/内存到阿里云 x86 规格的映射仍需继续完善
- 镜像资产治理仍以阿里云为中心，尚未扩展多云或多镜像源
- 单实例靶机启动能力尚未独立产品化
- 镜像制作链路尚未完整闭环
- 员工资源使用统计尚未建立
- 离线部署镜像包导出链路仍需按当前版本重新整理
