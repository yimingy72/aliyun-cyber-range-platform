# EIP 回收隔离修复与平台功能审核

基线为 master `831d9cd1`。本轮通过独立工作树修复同名 EIP 的回收误判，并审核七个业务模块的前后端主要读写、异步任务和权限路径。验证使用 Docker 与隔离数据库，没有对真实云资源执行创建、修改或删除。

## 修复的实际问题

### 同名 EIP 不再代表同一编排

阿里云未知 apply 结果的回收核验仍先检查本编排资源 ID 和归属标签。对于名称相同的其他 EIP，必须同时满足以下证据才能排除：

- 另一条平台实例记录，属于同一云工作空间、厂商、账号和地域。
- 云标签的管理标记、账号上下文、实例、用户、资源类型与该记录一致。
- 相同 EIP ID 对应另一编排未释放的费用台账，用户、账号、地域一致。
- 台账原始创建作业及云标签指向的作业都属于另一编排和当前空间，确为创建、重试或拓扑更新。

云标签在更新时可能指向新作业，台账仍保留原始创建作业，因此分别验证二者。EIP 是地域资源，同地域不同可用区的编排可以独立运行。无标签、重复/冲突标签、缺失记录、跨账号/空间、已释放台账和无有效来源的同名资源仍阻断清理完成。两轮云核验都会重新读取归属证据。

此路径只读取云端库存与平台记录，不会通过名称删除、接管或改写其他编排资源。现有 EIP 无需重建或改名。

Docker 测试覆盖两个不同编排同时完成清理、第三个运行编排及其 EIP/台账保持不变；本编排资源只剩台账记录、标签却声称属于另一编排时，也必须阻断。未决 apply 标记只在当前实例工作目录内、当前代际核验成功后清除。

### 网页启动的同一请求不会重复创建

单实例批次与编排启动使用同一次提交的稳定幂等键。API 使用已有数据库唯一约束保存受理记录；同键重放返回原结果，并发请求、参数冲突和结果未知不会再次执行创建。用户、云空间和操作类型分别隔离。保存的回执删除主机密码等凭据，实际访问仍走专用接口。

前端保存已提交参数，阻止同步重复点击；已受理后列表读取失败不会误报创建失败。未知结果显示“查询原请求”，完全相同的原请求直接使用冻结参数和原键取回执，不因等待后低于腾讯云最短有效期或规格下架而被首次创建校验拦住；原生表单约束也不会阻断查询。修改参数仍按新请求严格校验。

页面卸载、用户或工作空间变更后，旧响应不再导航或刷新新空间；旧令牌的迟到 401 也不会退出已经更新的会话。新增幂等 API 在两个服务实例共享的隔离 PostgreSQL 中验证。

### 账单与界面状态

- BSS 每页账号和月份必须匹配冻结账号与请求账期，缺失/错配的空响应不能清空旧日账。
- 官方金额必须满足十进制格式、数据库 Decimal(20,9) 和数值接口的精度；无效或超精度输入保留旧账，支持合法的小额收费和负数退款。
- 账单同步期间改变日期后，完成回调只触发当前筛选条件刷新，旧日期结果不能覆盖新界面。
- 单实例打包已受理后，列表刷新失败显示刷新错误，保留打包受理结果。
- MCP 凭据读取成功后才记成功审计，并等待审计持久化；VNC 审计也等待写入，避免拒绝访问被误记成功或产生未处理的异步错误。

| 编排实例 | 草稿/预览/应用绑定、旧主机保护、节点增删、回收与来源台账、另存保持原模板、DNS 状态及失败不重建 |

| MCP/接口 | scopes、JWT/令牌交换、owner 与空间边界、草稿 CAS、敏感结果与审计、90 个工具合同和 Skill 对齐 |
