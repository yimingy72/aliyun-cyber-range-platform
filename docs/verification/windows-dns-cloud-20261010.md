# Windows 多网卡 DNS 云上验证（2026-10-10）

通过本地 Docker 平台的 MCP，在已绑定的阿里云杭州和腾讯云南京账号执行；没有调用云 CLI、原始业务 API 或数据库来创建/销毁资源。

## 实测范围

- 阿里云：2 台 Windows Server 2019，每台 2 NIC；DNS 服务机仅配置主网卡，成员机仅配置辅助网卡。
- 腾讯云：同样 2 台双 NIC；另追加 1 台双 NIC 验证初始化后主网卡 DNS 保持修复。
- Windows 原生 DNS 角色建立 `dns-smoke.test` 及标准域控 SRV 记录；空的 `missing.dns-smoke.test` 用于确定性的解析失败。
- 每轮到期保护 45 分钟；追加单台为 35 分钟。达到测试条件后即提交整套回收。
- 不打包/导入/导出镜像，不创建快照或对象存储；临时目录资产来自两家云现有公共镜像。

## 发现并修复

1. HTTP DTO 未列入编译后 host.dns，导致模板创建被白名单拒绝；补严格嵌套校验及 HTTP 创建/保存/启动回归。
2. 腾讯 Windows 初始化/角色安装后主 NIC DNS 被覆盖；启动脚本在用户初始化结束时恢复选定策略，并提供有范围/账号/实例/nonce/CAS 约束的固定重新下发动作。
3. 平台脚本版本变化可能改变已有 host userdata；已有编排主机保持原 tfvars 字节，新主机使用新脚本，缺失原身份/变量证明拒绝更新。
4. 阿里云回收查询 VPC/VSwitch/NAT 分页大小曾超过官方 50 上限；精确校验及完整分页补充，不把权限错误、未知 400 或空成功体直接当作不存在。
