# 运行编排拓扑变更

本次开发基于 master 07904820，在 codex/runtime-topology 工作树进行。用户已确认采用“保存草稿 → 预览 → 确认应用”；删除在应用时回收真实云主机及随实例删除的磁盘，新主机继承原到期时间；支持多主机公网端口映射和纯内网拓扑。

## 使用流程

编排实例详情的“拓扑结构”可添加主机和交换机，编辑交换机 ACL、SNAT、DNAT，以及主机网卡的安全组规则。已有主机的镜像、规格、系统盘、密码、DNS、启动脚本和网卡身份保持冻结，已有交换机的网段和网络标识不可迁移。

“保存草稿”只保存设计。“预览变更”先保存当前版本，再返回新增主机、网络、回收主机、规则和关联网络资源清单。该清单是平台预期配置差异，不是实际 OpenTofu plan；预览令牌五分钟有效，绑定用户、云账号空间、草稿版本、原资源库存和到期时间。确认时原子消费令牌并创建一个更新作业。

worker 在实际 apply 前核对原生资源 ID、状态所有权和实际 plan，禁止未批准的旧主机创建、替换或删除，以及既有 VPC/子网迁移。新增资源必须归属冻结的云账号与平台用户。云变更开始后的失败不会声称全部回滚：保留状态、资源库存和费用记录，进入明确回收流程；不会自动重建整套实例。

“另存为新拓扑”从已保存草稿生成当前空间的新私有模板及初始版本。来源模板、来源关联、旧版本和云资源不变；运行凭据、原生云 ID 和状态不进入副本。相同请求使用同一幂等键，响应丢失后重放返回同一模板。不会自动发布。

至少保留一台主机。回收全部环境时使用编排实例列表的“销毁”，同时清理付费网络资源。
