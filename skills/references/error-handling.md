# MCP 错误处理

在 MCP 工具不可用、认证或权限失败、参数校验失败、确认响应、异步任务异常、超时或状态不一致时读取本文件。以当前工具响应、当前会话可见工具、类型化 schema、对应产品参考和资源状态为事实源。

## 总原则

1. 不绕过 MCP，不猜测 ID、参数、状态或替代规格。
2. 用户明确授权是写操作前提；仅在服务端实际返回 `confirmationId` 时执行二阶段确认。
3. 写操作结果未知时，先查询状态；只有当前服务实际支持时，才以相同幂等键恢复完全相同的请求。
4. 错误正文可能含凭据；面向用户的输出必须脱敏。

## 工具、认证与权限

| 现象 | 安全处理 |
|---|---|
| 工具未出现在当前会话 | 报告 MCP 未连接、工具未注册或被 scope 过滤；不要改用 HTTP 或 CLI。 |
| 当前 schema 未列出参数或约束 | 读取对应产品参考；出现类型化 schema 时始终以 schema 为准。 |
| 认证失效或会话无效 | 报告需要重新认证 MCP Server；不要尝试使用其他人的 Token 或身份。 |
| 401/403、scope 不足、owner/visibility 不匹配 | 说明缺少的权限或可见性；不要切换身份、扩大查询范围或绕过 API 校验。 |

## 参数、资源与状态

| 现象 | 安全处理 |
|---|---|
| 参数校验失败 | 复查对应产品参考、schema 类型和必填字段；不要猜测未声明默认值。 |
| 资源不存在 | 用最小范围 `list`/`get` 重新确认 ID 和可见范围；不要根据名称新建同名资源。 |
| 状态冲突 | 刷新实例、批次或作业状态；不要暴力重试不兼容操作。 |
| 规格不支持、容量不足或 `exactAvailable: false` | 停止创建，报告校验原因并请用户选择新的 CPU/内存；不要猜测替代规格。更改 CPU/内存后重新执行 `single_instance_spec_check`。 |
| 规格校验工具报错或超时 | 不得调用 `single_instance_batch_launch`；报告校验未完成，等待 MCP 或平台恢复后重新校验。 |

## 服务端确认与幂等

### 收到 `CONFIRMATION_REQUIRED`

1. 核对返回的目标、业务参数和影响范围是否与用户明确授权一致。
2. 仅在一致时，使用完全相同的业务参数和返回的 `confirmationId` 二次调用。
3. 若当前响应同时要求幂等键，保持原键；不要将确认 ID 用于其他资源、参数、用户或过期的预确认。

### 确认失效、重复或未知结果

- 确认 ID 失效：重新发起预确认；只要目标或参数改变，就重新取得用户授权。
- 当前服务未返回确认要求：不要发送或等待虚构的 `confirmationId`。
- 网络超时或响应中断：先查资源或作业状态；没有可确认的结果时，报告未知状态，不盲目重复创建。

## 异步任务与失败

- 返回操作、实例、批次或作业 ID 仅表示“已受理”，不代表云资源成功。
- 取得 `provisionJobId` 后，用 `provision_job_get` 查询进度与失败详情；不要把参数写成 `jobId`。
- 作业失败：报告脱敏后的失败详情和当前资源状态；仅在工具契约和状态允许时执行 retry。
- 达到 smoke test 成功条件后立即走销毁流程，并确认资源进入销毁终态。

## 未分类错误

保留安全的错误码、request ID、资源 ID 和非敏感状态以便排查。停止自行变通，并向用户说明下一项需要的授权、参数或平台侧修复。
