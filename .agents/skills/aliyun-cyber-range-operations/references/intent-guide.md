# 意图路由指南

在用户表述含糊、同时出现多个资源域，或涉及“实例”“镜像”“关闭”“访问”“重试”时读取本文件。当前会话实际暴露的工具与 scope 决定可调用能力；当前宽松 schema 未列出的参数约束由工具契约补充。

## 基本原则

1. 先按动作和资源域分流，再构造参数。
2. 通过最小范围 `list`/`get` 获得 ID；不要从名称猜测 ID。
3. 当前会话没有合适工具时，说明能力边界；不要改用 HTTP、数据库或云厂商命令。
4. 查询状态不等于请求凭据；凭据工具属于敏感操作。

## 资源域速查

| 用户表述 | 首选工具域 | 后续判断 |
|---|---|---|
| “模板”“一套靶场的蓝图”“启动靶场” | `range_template_*`、`range_instance_*` | 先确认模板，再区分查询模板还是启动整套靶场。 |
| “整套靶场”“环境”“拓扑”“范围实例” | `range_instance_*` | 查询、访问或完整销毁均针对整套靶场。 |
| “平台镜像”“可用镜像”“镜像资产” | `platform_image_*` | 区分查询、快照收录、私有/平台可见性变更和删除。 |
| “单台靶机”“独立实例”“训练主机”“一批主机” | `single_instance_*` | 区分单台、整批、创建、重试、重启、打包或导出。 |
| “可用实例规格”“CPU/内存是否可售” | `single_instance_spec_check` | 用用户给出的 CPU/内存只读校验；不得直调平台 HTTP API。 |
| “创建进度”“任务失败”“开通作业” | `provision_job_get` | 使用已知的 `provisionJobId`，不要把它写成 `jobId`。 |
| “用户”“角色”“禁用账号”“云配置” | `admin_user_*`、`cloud_config_*` | 必须是明确的管理员请求，且实际 scope/API 校验必须通过。 |

## 易混淆场景

### “创建实例”

- 用户说模板、靶场、环境或拓扑：优先理解为 `range_instance_launch`。
- 用户说平台镜像、CPU、内存、数量或单台训练机：优先理解为 `single_instance_batch_launch`。
- 无法判断时，只问一次：要基于靶场模板启动整套环境，还是基于平台镜像创建独立靶机？

### “查看实例”或“访问实例”

- 只问状态、名称、IP 以外的非敏感详情：使用相应的 `*_list` 或 `*_get`。
- 明确要求密码、SSH 信息、VNC 或访问入口：才使用 `*_get_access` 或 `single_instance_open_vnc`，并先读取敏感输出规则。
- 说“任务进度”而非实例详情：查询已知开通作业。

### “镜像”

- 查询可部署镜像：`platform_image_list`。
- 将已有云快照纳入平台：`platform_image_collect`；需要用户提供或先取得准确 `snapshotId`，不要猜测。
- 从独立靶机生成私有镜像：`single_instance_pack_image`。
- 让已有镜像在平台可见或恢复私有：`platform_image_publish` / `platform_image_unpublish`。
- 停止用于新建与彻底删除资产：分别是 disable 与 remove，影响不同，必须明确确认。

### “关闭”“删除”“回收”

- 当前工具域没有通用“关机”操作。不要把“关闭”擅自映射为重启或销毁。
- 明确要释放资源时，询问销毁范围：单台靶机、整个批次，还是整套综合靶场。
- 销毁是完整删除，必须取得用户明确授权并跟踪终态；若服务端返回确认要求，再按响应执行。

### “重试”与“重启”

- `retry` 用于创建或销毁失败的实例；先刷新状态并确认处于允许重试的失败状态。
- `reboot` 用于运行中的单台实例；不要用它代替失败重试。

## 创建前的最小信息

| 操作 | 至少需要确认的信息 |
|---|---|
| 启动整套靶场 | 模板、名称、过期时间。 |
| 创建独立靶机 | 平台镜像、CPU、内存、数量、过期时间；先读取规格参考，再用相同 CPU/内存执行 `single_instance_spec_check`。 |
| 收录平台镜像 | 准确快照 ID、显示名称。 |

不要默认 CPU、内存、数量、过期时间、密码或主机名。唯一可省略的已验证服务端默认值是系统盘 40 GiB；当前 schema 或工具契约要求的其他字段缺失时，向用户补问。

## 管理员边界

用户自称管理员不足以授权管理操作。管理员工具必须同时满足：用户明确提出具体变更、当前工具可见且 scope 足够、平台 API 的 owner/admin 校验通过。任一条件不满足时，报告阻塞原因，不切换身份或绕过权限。
